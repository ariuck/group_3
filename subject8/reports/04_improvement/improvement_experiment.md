# 개선 실험 설계 · 기록 (`kimchi_v5`)

> 산출물 4 · 가이드 20.3. 입력: Dataset `kimchi_v5` + [`failure_hypothesis.md`](../03_failure_analysis/failure_hypothesis.md) (v5 기준) · 지난 Version 분석은 `history/kimchi_v4/improvement_experiment.md`
> 숫자 근거: [`experiment_log.csv`](experiment_log.csv) · [`../runs_summary.csv`](../runs_summary.csv) · 실행별 `<실행>_training_condition.md` · Final 선택 [`../final_model_selection.md`](../final_model_selection.md) · 비교표 [`baseline_vs_improved.md`](baseline_vs_improved.md)

> **작성 시점 메모 (2026-10-20)**: 이 문서는 실험이 끝난 **뒤에** 정리했다. 각 실험의 변경 변수와 이유는 실행 당시 `experiment_log.csv` 에 적은 것을 그대로 옮겼고, 결과를 보고 이유를 고쳐 쓰지 않았다. 5라운드(exp051~065)는 코드만 있고 결과가 없어 4장에 "결과 없음"으로 적었다.

```text
Dataset kimchi_v5  +  baseline_v5 (YOLO11n · 640 · batch 16 · seed 42 · 50 epoch)
        ↓
실패 원인 가설 (H1 작은 이물 → 해상도 · H2 갈변 분포 차이 · …)
        ↓
한 번에 한 변수만 변경 → 같은 Validation 104장에서 비교
        ↓
채택 기준: 비교 대상보다 mAP50-95 +0.02 이상 (seed 흔들림 ±0.01 확인 뒤에는 seed 평균으로 비교)
        ↓
Final = Val 근거로 선택 → Frozen Test 한 번
```

## 1. 지킨 규칙

| 규칙 | 내용 |
|---|---|
| 같은 Dataset · 같은 Val | 모든 점수는 `kimchi_v5` Train 558 · Val 104. Val 점수는 **학습 중 best epoch** 의 값이고, Frozen Test 로 고르지 않았다 |
| 기준 조건 | Baseline = YOLO11n · imgsz 640 · batch 16 · seed 42 · epoch 50 · AdamW · lr0 0.001 · Ultralytics 기본 증강. 실험마다 바꾼 것만 다르다 |
| 채택 기준 | 비교 대상보다 mAP50-95 **+0.02 이상** (실험 사이 우연한 흔들림을 넘는 차이만 개선으로 본다) |
| 기록 | 좋아지든 나빠지든 지우지 않았다. 기각·재현성 확인·중단도 남겼다 |
| 사용하지 않은 데이터 | Frozen Test · Bridge Holdout (교과 14 용). **예외 1건**: 2026-10-16 Final 확정 전에 Test 점수를 한 번 본 적이 있다 (결과·스크립트는 지움, [`baseline_vs_improved.md`](baseline_vs_improved.md) 3장). 그 점수로 모델·조건을 고르지 않았고, 정식 Frozen Test 는 Final 확정 뒤 한 번 했다 |

## 2. 1라운드 — 한 변수씩 (Baseline 에서 출발)

| 실험 | 변경 변수 | 이유 (실행 당시 기록) | mAP50-95 | 판정 |
|---|---|---|---:|---|
| `baseline_v5` | — | v4 Val 누수 해소로 Dataset 이 바뀌어 같은 Version 에서 Baseline 재학습 (가이드 11.5·20.5) | 0.470 | 공식 Baseline |
| `exp001_v5_imgsz1280` | imgsz 640 → **1280** | 작은 이물 FN 대응 (H1) | 0.646 | 채택 +0.177 |
| `exp002_v5_imgsz1920` | imgsz 1280 → **1920** (batch 6 동반) | 1280 에서도 남은 작은 이물 FN | 0.704 | 채택 +0.058 |
| `exp003_v5_imgsz1920_epoch100` | epochs 50 → **100** | exp002 학습량 부족 여부 | 0.701 | 기각 -0.003 · 학습 2배 |
| `exp004_v5_tile2x2` | 입력 원본 → **2×2 조각** | 1920 축소에서도 작은 갈변이 10px 안팎으로 사라짐 (H1·H2) | 0.698* | 보류 +0.019* (기준 바로 아래) |

\* 타일링은 학습 중 Val 이 조각 단위라, 조각 예측을 합쳐 원본 Val 을 같은 코드(`src/tiling.py`)로 다시 채점한 값. 같은 코드로 잰 exp002 는 0.680 ([`tiling_eval.csv`](tiling_eval.csv)).

- 결과 요약: **해상도가 가장 큰 효과**였다 (640 → 1920 에서 +0.234). 가설 H1(작은 이물 → 해상도)이 맞았다.

## 3. 변수를 둘 바꾼 실험 (규칙 예외 — 사용자 결정)

한 변수 규칙을 지키지 못한 실험이다. 숨기지 않고 비교 방법을 같이 적는다.

| 실험 | 바꾼 것 | 어떻게 읽나 | mAP50-95 | 판정 |
|---|---|---|---:|---|
| `exp002` | imgsz + **batch 16 → 6** | GPU 12GB 한계 때문. nbs 64 gradient 누적이라 갱신 1번당 사진 수는 거의 같다. 엄밀한 한 변수는 아님 | 0.704 | 채택 |
| `exp006_v5_imgsz2560_aug` | **증강 + imgsz 2560** | exp005(증강만)와 비교하면 imgsz 하나 → 해상도 효과 +0.038 | 0.722 | 보류 (학습 **5시간 3분**) |
| `exp007_v5_s_imgsz1920_aug` | **증강 + 모델 11n → 11s** | exp005 와 비교하면 모델 하나 → 모델 효과 +0.040 | **0.724** | 채택 후보 (43분) |

- 증강은 11n 에서는 손해(-0.020), 해상도나 모델을 키운 뒤에는 이득이었다 (exp002 대비 exp006 +0.018 · exp007 +0.020).
- 이후 exp011(11s · **증강 끄기**, 0.716)이 exp007 보다 -0.008 이라 11s 에서는 증강을 유지했다.

## 4. 2~3라운드 — 후보 선택과 흔들림 측정

exp007 이 가장 좋았지만 한 번의 점수였다. 먼저 **같은 조건을 seed 만 바꿔 돌려** 흔들림을 쟀다.

| 실험 | 변경 | mAP50-95 | 알게 된 것 |
|---|---|---:|---|
| `exp013` (seed 7) | exp007 과 seed 만 다름 | 0.714 | **seed 만 바꿔도 ±0.01 흔들림** → 0.01 안쪽 차이는 의미 없음 |
| `exp014` (seed 123) | 같음 | 0.707 | 후보 A (11s · 1920) 평균 **0.715** (3개) |
| `exp008` (epoch 100) | exp007 + epochs 100 | 0.727 | +0.003 · 학습 2배 → 기각 |
| `exp012` (imgsz 1280) | exp007 + imgsz 1280 | 0.680 | -0.044 → 11s 에서도 해상도가 중요 |
| `exp010` · `exp010b` (타일링) | exp007 + 2×2 타일링 | 0.723* | 같은 코드 exp007 0.729 → 기각. **다른 PC 에서 소수 4자리까지 같음** (재현성 확인) |
| `exp011` (증강 끄기) | exp007 − 증강 | 0.716 | 증강 유지 |
| 추론 옵션 | TTA · agnostic NMS (exp007 · 008) | 0.716 · 0.715 (기본 0.731) | 둘 다 손해 → **Final 은 기본 추론 설정** (H4 기각) |

흔들림이 ±0.01 이라 **후보마다 seed 여러 개 평균**으로 비교하기로 했다.

| 후보 | 조건 | 실행 | 평균 |
|---|---|---|---:|
| A | 11s · 1920 · batch 3 | exp007 · 013 · 014 | 0.715 |
| **B** | **11s · 2240 · batch 2** | exp015 · 016 · 018 · 049 · 050 | **0.739** (0.726 ~ 0.749) |
| C | 11m · 1920 · batch 2 | exp009 (seed 1개, exp017 은 메모리 부족으로 중단·제외) | 0.730 |

- B 가 A 보다 +0.024 (기준 +0.02 초과) → 이후 개선 실험의 **기반 조건 = B**. C 는 B 와 비슷하고 더 무거워 선택하지 않았다.

## 5. 4라운드 — B 기반 개선 6방향 × seed 5개

기반 B 의 seed 3개가 0.726 · 0.732 · 0.746 으로 0.02 흔들려 채택 기준과 같았다 → **방향마다 seed 5개(42 · 7 · 123 · 1 · 2)**, B 도 5개로 맞춰 평균끼리 비교했다. 약점은 갈변 하나(H2)라 6방향 중 5개가 갈변을 겨눴다. 공식 `kimchi_v5` 는 바꾸지 않고, 복제·합성·복원은 그 실험의 학습 목록에만 썼다.

| 방향 | 바꾼 것 (B 대비) | 평균 | B 대비 | 갈변 mAP50-95 평균 | 판정 |
|---|---|---:|---:|---:|---|
| **B** | — | **0.739** | — | 0.108 | 기준 |
| ① 반점 복제 | 100px 미만 갈변 사진 8장 × 10 | 0.733 | -0.006 | 0.094 | 기각 |
| ② 반점 합성 | 반점을 Train 150장 배추 위에 약 300개 | 0.740 | +0.001 | 0.111 | 효과 없음 |
| ③ 2560 | imgsz 2240 → 2560 (batch 1) | 0.729 (3개) | -0.010 | 0.080 | 기각 (학습 1.4배) |
| ④ 복원 + 복제 | v3 개정 때 지운 Train 반점 13개 복원 + 복제 | 0.727 | -0.012 | 0.108 | 기각 |
| ⑤ 2560 + 복제 | ③ + ① | 0.732 | -0.007 | 0.091 | 기각 |
| ⑥ 2560 + 합성 | ③ + ② | 0.726 | -0.013 | 0.075 | 기각 |

- **B 보다 +0.02 이상 오른 방향이 없었다 → B 를 그대로 둔다.** B 안에서 Val 이 가장 높은 `exp050`(seed 2)을 Final 로 했다.
- 갈변은 6방향 모두 B 와 같은 범위 (0.075 ~ 0.111). ④ ≒ B → "v3 개정 때 반점을 지운 것"이 원인은 아니었다.
- ③ 의 seed 7 · 123 (exp026 · 027)은 처음 실행이 시작되지 못해 재학습 중이었다 (3개 평균). 결론은 바뀌지 않는다 (남은 두 개가 모두 0.80 이상이어야 평균이 +0.02 에 닿는다).
- B 모델을 학습 없이 큰 해상도로 예측: 2240 0.749 · 2560 0.751 · 2880 0.749 — 차이 없음.
- Val 최고점(0.749)은 seed 5개 중 최고를 고른 것이라 운으로 부풀어 있다. **Final 의 성능은 Frozen Test 점수로만 말한다.**

## 6. 5라운드 — 갈변 진단 (결과 없음)

Final 확정 뒤라 `exp050` 은 바꾸지 않는다. 진단: Train 반점 8개는 conf 0.35~0.95 로 전부 찾는데 Val 반점은 15개 중 2개 → 반점을 외웠다. Val 반점 중 9~10개는 conf 0.001 에서도 예측 박스가 나오지 않는다 (후보 단계에서 사라짐).

| 방향 | 바꾼 것 | 실행 | 상태 |
|---|---|---|---|
| ① P2 검출층 | `configs/yolo11s-p2.yaml` (stride 4 층 추가) · batch 1 | exp051 ~ 055 | **코드만 있고 결과 없음** |
| ③ 변형 합성 | 갈변 56개를 18~45px 로 줄여 변형해 붙임 (306개) | exp056 ~ 060 | 결과 없음 |
| ① + ③ | P2 + 변형 합성 | exp061 ~ 065 | 결과 없음 |

(`runs/` 와 `models/improved/` 에 exp051~065 가 없는 것을 확인했다. 결과가 나오면 이 장과 `final_model_selection.md` 를 갱신한다.)
