## 3. 원인 가설 (영향이 큰 순서)

### H1. Validation 의 나뭇잎·갈변은 Train 과 모습이 다르다 — DATA (분포 차이)

| 근거 | 내용 |
|---|---|
| Val 구성 | Val 84장 중 75장이 한 촬영 묶음 **G12** (나뭇잎 198개·갈변 65개 전부 G12) |
| 나뭇잎 | Train 나뭇잎은 **G16 의 빨간 꽃잎**(175/295개)·구겨진 종이가 대부분. Val 은 **짙은 갈색 마른 잎**(줄기 달림). 박스 크기 중앙값 Train 131px → Val 281px (×2.15) |
| 갈변 | Train 갈변은 **G09 의 넓게 썩은 잎**(221/254개, 181px). Val 은 **작고 흐린 반점**(57px, ×0.32). 두 경우 모두 교과 7 기준("변색된 부분 전체")대로 그려졌으므로 라벨 오류가 아니라 **갈변 모습 자체가 다름** |
| 학습 곡선 | Train cls_loss 는 끝까지 내려가는데(0.52) Val cls_loss 는 10~17 epoch 부터 2 전후에서 멈춤 → 학습 부족이 아니라 **처음 보는 모습을 분류하지 못함** |
| 그림 | `class0_leaf_paper_train_vs_val.jpg`, `class5_disease_browning_train_vs_val.jpg`, `class_error.jpg` |

- **원인**: 촬영 묶음마다 주로 찍은 이물이 다르고, 마른 잎·작은 반점 갈변이 G12 에만 있어서 Val 로 가면 Train 에는 그런 예가 거의 없다.
- **재학습만으로는 안 고쳐진다** (Epoch·모델 크기를 바꿔도 본 적 없는 모습은 배우지 못함).
- **대응 후보**: Split 정책에 "Class 의 주요 모습(하위 유형)이 Train 에 있어야 한다"는 기준을 추가해 재구성 (Dataset Version 변경), 또는 한계로 기록.

### H2. G00 시간순 블록 분할로 고추가 Train 에 거의 없다 — SPLIT (우리 설계 문제)

G00 은 **앞 25장은 파만, 뒤 25장은 파+고추**를 찍은 묶음이었다. 시간순 블록(1~26 Train / 27~34 Val / 35~42 Test / 43~50 Bridge)으로 자르니:

| 역할 | 파 | 고추 |
|---|---:|---:|
| Train | 127 | **3** |
| Validation | 16 | 24 |
| Frozen Test | 7 | 33 |
| Bridge Holdout | 6 | 34 |

(파/고추 구분: 박스 안 빨간 픽셀 비율 15% 기준, 수작업 분석)

- **원인**: G00 예외를 정할 때 "사진마다 배치가 다르다"만 확인하고 **묶음 안에서 대상이 시간에 따라 바뀌는지**는 확인하지 않았다.
- 결과: Val 고추 24개 → 대부분 플라스틱으로 예측 (빨간 플라스틱·스펀지와 혼동). Test·Bridge 도 같은 문제가 생긴다.
- **대응**: G00 을 파 구간(1~25)과 파+고추 구간(26~50)으로 나눠 **각 구간 안에서** 같은 비율로 블록 분할 → `kimchi_v2`. Train 이 바뀌므로 Baseline 을 다시 학습해야 한다 (가이드 11.5, "Train Label 수정 → Baseline 다시 학습").

### H3. 같은 물체에 두 Class 로 예측한다 — INFERENCE (추론 설정)

- FP 180개 중 **93개(52%)** 가 이미 다른 예측과 짝지어진 정답 위의 두 번째 박스다 (IoU ≥ 0.5). 예: 마른 잎 1개에 "나뭇가지 0.9" + "플라스틱 0.4".
- Ultralytics 기본 NMS 는 **Class 별로** 겹친 박스를 지우므로, Class 가 헷갈리는 물체는 박스가 두 개 남는다. H1·H2 의 Class 혼동이 FP 로도 나타나는 것.
- **대응**: 추론 때 `agnostic_nms=True` (Class 와 관계없이 겹친 박스 정리)를 Validation 에서 비교. **재학습 불필요**, 학습 변수가 아니라 추론 설정으로 따로 기록.

### H4. 작은 이물을 놓친다 — MODEL/TRAIN (입력 해상도)

| Class | 작은 박스 (< 150px) Recall | 중간 (150~300px) Recall |
|---|---:|---:|
| 나뭇가지 | 0.20 (3/15) | 0.80 |
| 벌레 | 0.47 (7/15) | 0.75 |
| 플라스틱 | 0.66 (27/41) | 0.86 |
| 갈변 | 0.00 (0/62) | 0.00 |

- 4K(4848px) 를 640 으로 줄이면 약 1/7.6 이 된다. Val 갈변 중앙값 57px → **약 7px**, 150px 박스 → 약 20px.
- **대응**: `imgsz` 640 → 1280 (갈변 57px → 약 15px). 가이드 기본 예시는 960(→ 약 11px). RTX 3060 에서 batch 16 유지 가능 (640 에서 GPU 2.1GB).

### H5. 정상 김치 조각을 이물로 본다 — DATA (Negative 부족)

- FP_BACKGROUND 23개는 전부 김치 자체: **짙은 녹색 잎끝 → 나뭇가지**, **반투명 배추 조각 → 플라스틱**.
- 정상 김치(이물 없음) 사진이 데이터에 0장이라, 모델이 "이물이 아닌 김치"를 따로 배울 기회가 적다.
- **대응**: 교과 8 데이터 안에서는 해결 수단이 없다 → 한계로 기록, 교과 14 실제 촬영 데이터에서 정상 사진 확보.
