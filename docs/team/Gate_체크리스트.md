## 1. 데이터 조사 결과 (3번) — 바탕화면 원본 폴더를 읽기만 해서 센 값

| source_dataset | original_split | image_count | label_count | pair_count | empty_label_count |
|---|---|---:|---:|---:|---:|
| 이물검출_학습데이터1 | train | 500 | 500 | 500 | 0 |
| 이물검출_학습데이터2 | train | 220 | 220 | 220 | 0 |
| 이물검출_학습데이터2 | validation | 180 | 180 | 180 | 0 |
| **합계** | | **900** | **900** | **900** | **0** |

Class 분포 (BBox 수):

| Class | 이름 | BBox 수 |
|---:|---|---:|
| 0 | 나뭇잎·종이류 | 716 |
| 1 | 플라스틱류·돌·금속 | 1831 |
| 2 | 나뭇가지류 | 911 |
| 3 | 벌레류 | 379 |
| 4 | 고무장갑 (사용 안 함) | 0 |
| 5 | 병해·갈변 | 313 |
| 6 | 파·고추 | 249 |
| 합계 | | 4399 |

알게 된 점:
- 가이드 기준(900장 / 900개)과 일치하고, **짝이 안 맞는 파일이 없다**
- 읽을 수 없는 줄 0줄, 0~6 범위를 벗어난 Class 없음, **Class 4 는 한 개도 없다**
- **빈 TXT 가 0개** → "BBox 가 하나도 없는 정상 김치 사진"은 없다 (모든 TXT 에 한 줄 이상 있음). 정상 김치 사진이 따로 섞여 있는지는 **사진을 직접 봐야** 알 수 있다
- Class 1(플라스틱류·돌·금속)이 가장 많고 Class 6(파·고추)이 가장 적다 → 교과 8 에서 Class 별 성능을 볼 때 참고

## 3. 실제 사진 1장 End-to-End (9·10번)

| 순서 | 할 일 | 확인 |
|---:|---|:-:|
| 1 | [📂 이미지 열기] → `data\raw\...\images\...` 에서 사진 1장 선택 | ☐ |
| 2 | 상단 "출처: 데이터셋 / split" 이 맞게 표시된다 | ☐ |
| 3 | 상태줄에 "RAW(원본) TXT 에서 BBox N개 로드" — **TXT 줄 수 = 오른쪽 BBox 개수** | ☐ |
| 4 | BBox 가 실제 물체 위치에 맞다 | ☐ |
| 5 | BBox 하나 추가(드래그) 후 [💾 저장] | ☐ |
| 6 | `data\work\<데이터셋>\labels\<split>\` 에 TXT 가 생겼다 ([📁 WORK 폴더 열기]) | ☐ |
| 7 | BBox 를 지운 뒤 [🔄 다시 불러오기] → **같은 위치에 복원**된다 | ☐ |
| 8 | `data\raw` 의 같은 TXT 파일은 **수정한 날짜가 그대로**다 | ☐ |

여덟 개가 모두 ☑ 이면 9번과 10번 통과. 막히면 `docs/design/EndToEnd_실행계획.md` 의 "실패하면 먼저 볼 곳" 참고.
