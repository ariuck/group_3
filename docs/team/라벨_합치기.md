# 팀원 라벨 합치기

팀원이 라벨링한 TXT 를 내 `data/work/` 로 모으는 방법입니다. **데이터(TXT 포함)는 NDA 대상이라 Git·개인 클라우드·메신저로 보내지 않습니다.** 팀이 정한 허용된 방법(회사 공유 폴더, USB 등)으로 받으세요.

## 보내는 쪽: 결과를 파일 하나로 묶기

라벨(txt)과 검수표를 한 번에 압축 파일 하나(1MB 안팎)로 묶습니다.

```bash
python tools/pack_results.py
```

- `data/share/결과_날짜_시각.zip` 이 만들어집니다. (`data/` 아래라 Git 에서 제외)
- 라벨(`.txt`)과 검수표만 들어가고, 사진(jpg)·`Zone.Identifier`·`_session.json` 은 들어가지 않습니다. 몇 개를 담았는지 알려 줍니다.
- Windows 에서 보려면 탐색기 주소창에 `\\wsl$\Ubuntu\home\<사용자>\group_3\data\share` 를 붙여넣습니다.

## 전달하는 방법 (USB 가 없을 때)

데이터이므로 **허용된 방법**으로만 전달합니다. 인터넷 서비스(메신저·클라우드)는 팀 기준이 금지하므로, 먼저 강사님께 허용되는 방법을 확인하세요. 확인 전에는 인터넷을 거치지 않는 아래 방법을 쓰세요.

| 방법 | 어떻게 |
|---|---|
| **Windows 근거리 공유** (같은 공간) | 설정 ▸ 시스템 ▸ 근거리 공유를 두 PC 모두 켭니다. zip 파일을 우클릭 ▸ 공유 ▸ 상대 PC 를 선택합니다. 인터넷을 거치지 않습니다 |
| **공유 폴더** (같은 와이파이·랜) | 받는 쪽 PC 에서 폴더를 우클릭 ▸ 속성 ▸ 공유로 공유하고, 보내는 쪽이 `\\받는PC이름\폴더` 로 접속해 zip 을 복사합니다 |
| **한 PC 에 모여서** | 받을 사람 PC 에 직접 복사합니다 |

## 받는 쪽: 풀어서 내 PC 에 넣기

zip 을 아무 폴더(예: `C:\받은결과`)에 풉니다. 그다음 WSL 에서:

```bash
python tools/import_labels.py /mnt/c/받은결과 --apply                 # 라벨(txt)
python tools/merge_manifests.py /mnt/c/받은결과/검수표.csv --apply     # 검수표 (내 파일과 자동으로 함께 합쳐짐)
```

## 왜 탐색기로 복사하면 안 되나

받은 파일에는 Windows 가 "인터넷에서 받음" 표시(`ZoneId=3`)를 붙여 둘 수 있습니다. 탐색기로 WSL 폴더에 복사하면 이 표시가 `파일명.txtZone.Identifier` 라는 별도 파일로 같이 들어오고, 경우에 따라 진짜 `.txt` 가 빠지기도 합니다. 프로그램과 Validation 은 `.txt` 만 읽어서 문제는 없지만 폴더가 지저분해집니다.

## 가져오는 방법 (권장)

받은 폴더를 Windows 어디에 두든, 프로젝트 폴더에서 아래 순서로 실행합니다.

```bash
python tools/import_labels.py <받은 폴더>
```

먼저 **미리보기**가 나옵니다. (아무것도 복사하지 않음)

| 항목 | 뜻 |
|---|---|
| 새 라벨 | 내 작업 폴더에 없는 것 → 복사됨 |
| 이미 같은 내용 | 이미 같은 파일이 있음 → 건너뜀 |
| 이름은 같고 내용이 다름 | **충돌.** 같은 사진을 두 사람이 저장한 것 → 기본은 복사하지 않음 |
| raw 에 없는 이름 | `data/raw` 에 같은 이름의 사진이 없음 → 복사하지 않음 |
| 넣을 곳을 정할 수 없음 | 같은 이름의 사진이 여러 곳에 있음 → 받은 폴더 경로에 데이터셋·split 이름이 있으면 구분 |
| 형식 오류 | Class 범위 밖, 좌표 범위 밖 등 → 복사하지 않음 |

문제가 없으면 같은 명령에 `--apply` 를 붙입니다.

```bash
python tools/import_labels.py <받은 폴더> --apply
```

- 새 라벨만 복사하고 `.txt` 가 아닌 파일(Zone.Identifier 등)은 무시합니다. 원본(`data/raw`)은 읽기만 합니다.
- 충돌은 어느 쪽이 맞는지 확인한 뒤, 받은 쪽으로 바꾸려면 `--overwrite` 를 붙입니다.
- 폴더 구조가 달라도 됩니다. 어느 데이터셋·split 에 넣을지는 사진 이름으로 찾습니다.

## 이미 들어온 표시 파일 지우기

```bash
find data/work -name '*Zone.Identifier' -delete
```

## 검수표(CSV) 합치기

검수표에도 실제 사진 파일명이 들어 있어 **회사 데이터이므로 Git 에 올리지 않습니다.** 라벨 TXT 와 같은 허용된 방법으로 팀원의 `manifests/dataset_manifest.csv` 를 받아서, 이름을 구분해 `data/inbox/` 폴더에 모아 둡니다. (예: `동훈.csv`, `혜성.csv`) `data/` 아래는 Git 에서 자동으로 제외됩니다. **`manifests/` 아래에 하위 폴더를 만들어 두면 제외되지 않으니 거기에는 두지 마세요.**
내 검수표(`manifests/dataset_manifest.csv`)는 따로 넣지 않아도 **자동으로 함께 합쳐집니다.**

```bash
python tools/merge_manifests.py data/inbox
```

먼저 **미리보기**가 나옵니다. (아무것도 쓰지 않음)

| 항목 | 뜻 |
|---|---|
| 같은 내용이라 하나로 합친 줄 | 같은 사진이 여러 파일에 같은 내용으로 있음 → 하나만 남김 |
| 내용이 달라 고른 줄 | **충돌.** 같은 사진을 두 사람이 다르게 적음 → ① 검수 전이 아닌 줄 ② 검수일이 늦은 줄 ③ 뒤에 넣은 파일 순으로 고르고 어떤 사진인지 알려 줌. 알려 준 사진은 직접 확인 |
| 상태별 | 검수 전 / 수정 완료 / 검수 완료 / 수정 필요 / 제외 줄 수 |
| 작성자가 비어 있는 줄 · 작성자와 검수자가 같은 줄 | 교차검수 규칙(작성자와 검수자는 달라야 함) 확인용 |
| 미처리 REVIEW | `수정 필요` 이면서 `발견된 문제`가 `REVIEW` 로 시작하는 줄. FINAL 로 넘기기 전에 0건이어야 함 |
| 검수표에 줄이 없는 사진 | 원본 900장 중 아직 줄이 없는 사진 수 |

문제가 없으면 `--apply` 를 붙여 저장합니다. **기본 저장 위치는 프로그램이 쓰는 `manifests/dataset_manifest.csv`** 입니다. `-o 이름.csv` 로 다른 이름을 정할 수도 있습니다.

```bash
python tools/merge_manifests.py data/inbox --apply
```

- **덮어쓰기 전에 백업**: 저장할 파일이 이미 있으면 같은 폴더에 `dataset_manifest.백업-날짜_시각.csv` 로 그대로 복사해 둡니다. (`manifests/*.csv` 라서 Git 에서 제외됩니다. 문제가 없으면 지워도 됩니다)
- 프로그램을 **끈 상태에서** 합치세요. 켜 둔 채로 저장하면 프로그램이 이전 내용으로 다시 쓸 수 있습니다.
- 합친 뒤 사진 순서대로 정렬하고 `No` 를 1부터 다시 매깁니다. `data/inbox` 의 파일은 고치지 않습니다.
- **출처 데이터셋·split 이 틀린 줄**: 팀원 컴퓨터에서 사진 폴더 구조가 달라 `출처 데이터셋` 에 `project`, `data` 같은 폴더 이름이 적히고 `원래 split` 이 비어 있는 경우가 있습니다. 도구는 사진 이름으로 `data/raw` 에서 실제 위치를 찾아 **자동으로 바로잡고**, 바로잡은 줄 수를 파일별로 알려 줍니다. 바로잡을 수 없는 줄(원본에 없는 사진 등)은 **조용히 빼지 않고 알려 주며, 그런 줄이 있으면 저장하지 않습니다.**
- 머리글(19칸)이 다르거나 엑셀 cp949 로 저장된 파일이 있으면 **어느 파일이 문제인지** 알리고 중단합니다. (엑셀에서는 'CSV UTF-8' 로 저장)
