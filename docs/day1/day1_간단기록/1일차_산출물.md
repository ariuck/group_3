# 교과 7 · 1일차 산출물 (간단판)

> **1일차에 가능한 만큼만** 만듭니다. 사진 3~5장으로 확인한 내용을 기준으로 적고, 900장 전체 조사는 2~3일차에 합니다.

## 1. 데이터 조사표 (사진 3~5장 기준)

### 1-1. 폴더 구조 확인

```text
이물검출_학습데이터1/        이물검출_학습데이터2/
├─ images/train/             ├─ images/train/ , images/validation/
└─ labels/train/             └─ labels/train/ , labels/validation/
```

| 확인 | 내 결과 |
|---|---|
| images 와 labels 폴더가 있다 | 【내 칸】 O / X |
| train / validation 구분이 있다 | 【내 칸】 어느 데이터셋에? |
| 이미지 1장 ↔ 같은 이름 TXT 1개 | 【내 칸】 O / X |

### 1-2. 사진 3장 살펴보기 (예: 한 장씩 열어 보기)

| No | 파일 | 출처 / split | BBox 수 (TXT 줄 수) | Class | 이미지 유형 | 확인 결과 |
|---:|---|---|---:|---|---|---|
| 1 | 250424_000001.jpg **(예시)** | 샘플데이터1 / train | 2 | 2, 3 | 김치 + 대상 객체 | TXT 2줄 = 화면 BBox 2개, 위치 맞음 |
| 2 | 250424_000002.jpg **(예시)** | 샘플데이터1 / train | 0 (빈 TXT) | — | 정상 김치 | 이물 없음 → **빈 TXT 가 정상 정답** |
| 3 | 250424_000005.jpg **(예시)** | 샘플데이터1 / train | 1 | 2 | 대상 객체 단독 | 김치가 없어도 **검수 대상**, BBox 정상 |
| 4 | 【내 칸】 | | | | | |
| 5 | 【내 칸】 | | | | | |

### 1-3. 이 조사로 알게 된 것 (3줄이면 충분)

- 이미지 유형은 **김치+대상 / 정상 김치 / 대상 단독** 이 섞여 있다 → 【내 칸】 내가 본 사진에서는?
- 빈 TXT 는 **오류가 아니라 정상 이미지일 수 있다**
- 같은 Class 라도 사진마다 BBox 크기가 다르다 → 【내 칸】

> 900장 전체의 개수(JPG/TXT/Pair/Class 분포)는 2~3일차에 조사합니다. (프로그램의 **[📊 데이터 조사]** 버튼으로 바로 조사할 수 있습니다)

## 2. Class / BBox 기준 정리 (한 장)

### Class — 회사 제공 번호 그대로 (바꾸지 않음)

| ID | 이름 | 사용 |
|---:|---|---|
| 0 | 나뭇잎·종이류 | 사용 |
| 1 | 플라스틱류·돌·금속 | 사용 |
| 2 | 나뭇가지류 | 사용 |
| 3 | 벌레류 | 사용 |
| 4 | 고무장갑 | **사용 안 함** (발견되면 지우지 말고 **REVIEW**) |
| 5 | 병해·갈변 | 사용 |
| 6 | 파·고추 | 사용 |

- **김치는 Class 가 아니다** → 김치에는 BBox 를 그리지 않는다
- "정상 김치 / 대상 단독 / 김치+대상" 은 **이미지 유형**이지 Class 가 아니다 (새 번호를 만들지 않는다)

### BBox — 5가지 약속

```text
1. 객체 전체를 포함한다 (일부를 자르지 않는다)
2. 객체 경계에 가깝게, 배경은 최소로
3. 서로 다른 객체는 BBox 를 따로 그린다
4. 아주 작아도 종류를 알 수 있으면 빼먹지 않는다
5. 애매하면 추측하지 말고 REVIEW
```

### 검수 상태 3가지 (오늘은 이것만)

| 상태 | 언제 | 예 |
|---|---|---|
| **PASS** | 기존 라벨이 맞다 | 사진 1: 2개 모두 정확 |
| **EDITED** | 고쳤다 (추가·삭제·Class 변경·크기 수정) | 빠진 이물 BBox 추가 |
| **REVIEW** | 판단이 어렵다 | Class 4 처럼 보이는 것 |

## 3. Dataset Manifest 초안

Manifest = 사진 한 장 한 장의 **출처 · 상태 · 메모**를 적는 작업대장(CSV). 프로그램이 이 형식으로 자동 저장합니다.

| 필드 | 뜻 | 예시 |
|---|---|---|
| `image_name` | 이미지 파일명 | 250424_000001.jpg |
| `source_dataset` | 어느 데이터셋에서 왔나 | 샘플데이터1 |
| `original_split` | 원래 train 이었나 validation 이었나 | train |
| `scene_type` | 이미지 유형 (Class 아님) | kimchi_with_target |
| `assignee` / `reviewer` | 작업자 / 검수자 | A / (비어 있음) |
| `status` | 상태 | EDITED |
| `original_bbox_count` → `final_bbox_count` | 원본 BBox 수 → 최종 BBox 수 | 2 → 3 |
| `note` | 메모 | 병해·갈변 1개 추가 |

**(예시) 3줄** — 위 사진 3장:

| image_name | source_dataset | original_split | scene_type | status | bbox 수 | note |
|---|---|---|---|---|---|---|
| 250424_000001.jpg | 샘플데이터1 | train | kimchi_with_target | EDITED | 2 → 3 | 병해·갈변 1개 추가 |
| 250424_000002.jpg | 샘플데이터1 | train | normal_kimchi | PASS | 0 → 0 | 이물 없음 확인 |
| 250424_000005.jpg | 샘플데이터1 | train | object_only | PASS | 1 → 1 | 대상 단독, 정상 |

> `scene_type` 은 YOLO TXT 에 들어가지 않는 **메타데이터**입니다. (교과 8 에서 데이터 분포를 볼 때 사용)

## 5. 1장 End-to-End 실행 계획 · 결과

### 계획

```text
① 사진 1장 열기
        ↓
② 같은 이름 TXT 가 자동으로 읽히고 BBox 가 보이는가?
        ↓
③ BBox 를 하나 추가한다 (또는 삭제 / Class 변경)
        ↓
④ 저장한다 → WORK 에 TXT 가 생기는가?
        ↓
⑤ [다시 불러오기] → 같은 위치에 BBox 가 나오는가?
        ↓
⑥ 원본(RAW) TXT 는 그대로인가?
```

### 성공 기준 (6개 모두 O 여야 통과)

| 확인 | 샘플 시험 (예시) | 내 사진으로 시험 |
|---|:-:|:-:|
| 이미지가 정상으로 보인다 | O | 【내 칸】 |
| TXT 줄 수 = 화면 BBox 수 | O (2 = 2) | 【내 칸】 |
| BBox 가 객체 위치에 맞다 | O | 【내 칸】 |
| 추가한 BBox 가 WORK 에 저장된다 | O (2줄 → 3줄) | 【내 칸】 |
| 다시 불러오면 같은 위치에 복원된다 | O (3개 복원) | 【내 칸】 |
| 원본 TXT 가 안 바뀐다 | O (원래 2줄 그대로) | 【내 칸】 |

### 결과 (샘플 사진, 프로그램 실제 실행 화면)

## 6. 교과 8 과 이어지는 점 (왜 이렇게 기록하는가)

교과 8 문서(데이터 사용 · 성능평가 · 전체 흐름)에서 가져온 내용입니다.

| 오늘 하는 일 | 교과 8 에서 필요한 이유 |
|---|---|
| `source_dataset` · `original_split` 기록, 폴더 구조 유지 | 교과 8 에서 Train / Validation / Frozen Test / Bridge Holdout 을 나눌 때 **출처와 기존 분할**을 확인해야 함. 같은 촬영 조건의 비슷한 사진이 Train 과 Test 에 같이 들어가면(Data Leakage) 안 됨 |
| 900장을 **합치지 않고** 전수 검수 | 교과 7 은 900장을 모두 검수하지만, 교과 8 은 일부(예: 약 150장)를 모델 개발에 쓰지 않고 따로 보존함 — 지금 섞으면 나중에 나눌 수 없음 |
| `scene_type` 기록 | 정상 김치 / 김치+대상 / 대상 단독 비율을 보고 분할·평가 방식을 정함 |
| RAW 는 수정하지 않고 WORK 에서 수정 | 원본이 보존되어야 교과 8 Dataset Audit 이 가능 |
| Class 번호 그대로 유지 | 교과 8 은 이 기준을 **바꾸지 않고 그대로** 사용 |

### 라벨 품질이 모델 평가에 영향을 주는 이유

| 라벨 문제 | 모델 평가에서 생기는 일 |
|---|---|
| 이물이 있는데 BBox 가 없음 | 모델이 맞게 찾아도 틀린 것(FP)으로 계산될 수 있음 |
| 정상 김치인데 BBox 가 있음 | 모델이 "없다"고 하면 놓친 것(FN)으로 계산될 수 있음 |
| BBox 가 너무 크거나 작음 | 정답 BBox 와 겹치는 정도(IoU)가 낮아져 mAP 가 낮게 나옴 |
| Class 가 틀림 | Class 별 성능이 왜곡됨 |

→ 그래서 교과 7 의 BBox 5가지 약속과 REVIEW 규칙이 중요합니다.

### 현재 구현과 교과 8 문서의 차이 (확인 필요)

- 교과 8 문서는 WORK 도 RAW 와 **같은 폴더 구조**(`데이터셋/images|labels/split`)를 유지하라고 합니다.
- 이 프로그램은 WORK 에 **라벨 TXT 만** RAW 와 같은 구조(`work/<데이터셋>/labels/<split>/xxx.txt`)로 저장합니다. (이미지는 용량 때문에 복사하지 않고 RAW 에서 읽음. 데이터셋·split 정보는 유지됨)
- 교과 8 문서의 구조와 같습니다. (폴더 골격은 `data/work/` 에 미리 만들어 두었습니다)
