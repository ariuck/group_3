# 1. 데이터 조사표

> **받은 데이터가 실제로 어떻게 생겼는지** 직접 열어 보고 숫자와 판단을 적는 표입니다.
> 표가 2개 있습니다. **A = 폴더별 수량(숫자 세기)**, **B = 사진 몇 장 직접 보기**

## 먼저 읽기 — 칸에 무엇을 적나?

| 칸 | 적는 것 |
|---|---|
| `【개수】` 자리 | **폴더를 열어 직접 센 숫자**만 적는다 (지어서 쓰지 않는다) |
| 아직 데이터가 없다 | `【개수】` 를 그대로 두거나 비워 둔다 |
| `(예시·가짜 샘플)` 이 붙은 줄 | 설명용 가짜 값 — 내 사진으로 **바꿔서** 적는다 |

> 폴더 안의 파일은 **보기만** 한다. 지우거나 이름을 바꾸거나 고치지 않는다 (원본 보호).

---

## A. 폴더별 수량표 (`dataset_inventory`)

폴더 3곳을 **합치지 않고 따로** 적습니다. (교과 8 에서 "어디서 온 데이터인지" 가 중요하기 때문)

| source_dataset | original_split | image_count | label_count | pair_count | empty_label_count |
| -------------- | -------------- | ----------: | ----------: | ---------: | ----------------: |
| dataset1       | train          |         500 |         500 |        500 |                 0 |
| dataset2       | train          |         220 |         220 |        220 |                 0 |
| dataset2       | validation     |         180 |         180 |        180 |                 0 |
| **합계**       |                |     **900** |     **900** |    **900** |             **0** |

> 위 숫자는 바탕화면 `원본파일\이물검출_학습데이터1·2` 폴더를 **읽기만 해서** 센 값입니다. (`empty_label_count` 는 **크기가 0 인 TXT** 기준)

### 머리글 뜻

| 영어 | 한글 뜻 | 적을 숫자 | 세는 방법 |
|---|---|---|---|
| `source_dataset` | 출처 데이터셋 | (이름) dataset1 / dataset2 = `이물검출_학습데이터1` / `…2` | — |
| `original_split` | 원래 분할 | (이름) train / validation | — |
| `image_count` | 이미지 개수 | JPG 사진이 몇 장인가 | `images\…` 폴더의 JPG 개수 |
| `label_count` | 라벨 개수 | TXT 파일이 몇 개인가 | `labels\…` 폴더의 TXT 개수 |
| `pair_count` | 짝 개수 | **같은 이름**의 JPG-TXT 가 몇 쌍인가 | 이름이 서로 맞는 것만 |
| `empty_label_count` | 빈 라벨 개수 | **내용이 빈** TXT 가 몇 개인가 | 크기가 0KB 인 TXT |

(`train` = 모델이 배우는 데이터, `validation` = 잘 배웠는지 확인하는 데이터. 회사 데이터에 이미 나뉘어 있어서 **그대로 유지**)

### 숫자를 센 뒤 확인 (O / X)

| 확인 | 결과 |
|---|:-:|
| 합계가 이미지 **900**, TXT **900** 인가 (가이드 기준) | 【O/X】 |
| `image_count = label_count = pair_count` 인가 (짝이 모두 맞는가) | 【O/X】 |
| 맞지 않는다면 어느 폴더 · 어느 쪽이 남는가 | 【메모】 |

- `pair_count` 가 `image_count` 보다 작다 → **TXT 없는 사진**이 있다 (파일명을 이슈로 기록, 고치지 않는다)
- `label_count` 가 더 크다 → **사진 없는 TXT** 가 있다
- `empty_label_count` 가 크다 → 정상 김치 사진이 많을 수 있다 (확정은 눈으로 본 뒤)

(예시·가짜 값, 설명용) `dataset1 / train` 에서 사진 300장 · TXT 300개 · 짝 300쌍 · 빈 TXT 40개 였다면 → `300 | 300 | 300 | 40`

## B. 사진 몇 장 직접 보기 (3~5장)

앞쪽 파일만 고르지 말고 **유형이 섞이게** 고릅니다. (김치+대상 / 정상 김치 / 대상 단독, train 과 validation 에서 각각)

| No | 파일명 | source_dataset | original_split | 이미지 유형 | TXT 줄 수 (BBox 수) | Class | 줄 수 = 화면 BBox 수 | 위치 맞음 | Class 맞음 | 메모 |
|---:|---|---|---|---|---:|---|:-:|:-:|:-:|---|
| 1 | 250424_000001.jpg (예시·가짜 샘플) | 샘플데이터1 | train | 김치 + 대상 객체 | 2 | 2, 3 | O | O | O | 정상 |
| 2 | 250424_000002.jpg (예시·가짜 샘플) | 샘플데이터1 | train | 정상 김치 | 0 (빈 TXT) | — | O | — | — | 이물 없음 → **빈 TXT 가 정답** |
| 3 | 250424_000005.jpg (예시·가짜 샘플) | 샘플데이터1 | train | 대상 객체 단독 | 1 | 2 | O | O | O | 김치가 없어도 검수 대상 |
| 4 | 【내 사진】 | | | | | | | | | |
| 5 | 【내 사진】 | | | | | | | | | |

### 칸마다 어디서 알아내나

| 칸 | 방법 |
|---|---|
| 파일명, source_dataset, split | 프로그램 제목줄 / 파일 경로 |
| 이미지 유형 | **눈으로 보고 판단** |
| TXT 줄 수 (BBox 수) | 프로그램 오른쪽 **라벨 목록의 개수** (또는 TXT 를 메모장으로 열어 줄 수) |
| Class | 라벨 목록의 `cls` 번호 |
| 줄 수 = 화면 BBox 수 | 위 두 숫자가 같으면 O |
| 위치 맞음 / Class 맞음 | 이미지를 보고 BBox 가 객체를 감싸는지, 이름이 맞는지 |

---

## 알게 된 것 (3줄)

- 이미지 유형은 **김치+대상 / 정상 김치 / 대상 단독** 이 섞여 있다 → 【내가 본 사진에서는】
- **빈 TXT 는 오류가 아니다** (정상 김치일 수 있다)
- 같은 Class 라도 사진마다 BBox 크기가 다르다 → 【내가 본 것】

## 조사하면서 지킬 것

- `train / validation` 을 **섞지 않는다**, 폴더 3곳을 한 곳으로 합치지 않는다
- 정상 김치 · 대상 단독 사진을 **삭제하거나 따로 빼지 않는다**
- Class **4** 가 보이면 지우지 말고 메모 (나중에 REVIEW)

폴더 전체 개수는 프로그램의 **[📊 데이터 조사]** 버튼이 한 번에 세어 줍니다. (결과 표를 **복사**해서 위 A 표에 붙여 넣을 수 있음)
