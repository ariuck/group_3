# Class Labeling Guide

> 라벨링할 때 **"이 객체를 몇 번 Class 로 저장해야 하는가?"** 를 팀원 모두가 같은 기준으로 판단하기 위한 문서입니다.
> 이 기준은 900장 검수와 교차검수에 그대로 적용합니다. 프로그램의 Class 설정은 `configs/classes.yaml` 입니다.
> BBox 를 어디까지 그리는지는 [bbox_guide.md](bbox_guide.md), 검수표 작성은 [manifest_guide.md](manifest_guide.md) 를 봅니다.

## 공통 원칙

- 사용 Class: 0~6 (번호를 바꾸지 않는다). **Class 4 는 사용하지 않는다.**
- 김치 자체는 검출 대상 Class 가 아닙니다. 김치에는 BBox 를 그리지 않습니다.
- 정상 김치 / 김치+대상 / 대상 단독 은 **이미지 유형**이지 Class 가 아닙니다.
- **한 객체 = BBox 1개 = Class 1개**입니다. 한 BBox 에 두 Class 를 섞지 않습니다.
- Class 는 **재질·형태가 눈으로 확인될 때만** 지정합니다. 확인할 단서가 없으면 추측하지 않고 REVIEW 입니다.
- 객체가 서로 다른 Class 와 겹쳐 있어도 각각 따로 BBox 를 그립니다.

## Class 한눈에 보기

| ID | 이름 | 한 줄 기준 | 한 BBox 의 단위 | 실제 라벨의 크기(짧은 변 중앙값) |
|---:|---|---|---|---:|
| 0 | 나뭇잎·종이류 | 납작하고 얇은 **잎 또는 종이** 조각 | 잎 1장 / 종이 1조각 | 약 200px |
| 1 | 플라스틱류·돌·금속류 | 식물이 아닌 **단단한 이물** (플라스틱·돌·금속) | 조각 1개 | 약 154px |
| 2 | 나뭇가지류 | **목질(나무)** 의 막대·가지 | 가지 1개 (곁가지 포함) | 약 185px |
| 3 | 벌레류 | **곤충·벌레**의 몸 형태가 확인되는 것 | 한 마리 | 약 100px |
| 4 | 고무장갑 | **사용 안 함** → 발견되면 REVIEW | – | – |
| 5 | 병해·갈변 | 식재료가 **변색·병든 부위** | 이어진 변색 덩어리 1개 | 약 125px |
| 6 | 파·고추 | **파 또는 고추** 조각 | 조각 1개 | 약 125px |

> 크기는 참고입니다. 실제 라벨 4399개를 집계한 값이며, 이보다 아주 작거나 큰 BBox 는 한 번 더 확인합니다.
> (이미지는 4848×2704, BBox 의 짧은 변 전체 중앙값 약 150px)

## 어떤 Class 인지 정하는 순서

```text
1. 식재료 표면의 색 변화인가? (떼어낼 수 없다)     → 아래 5 표에서 단서 2개 이상이면 Class 5, 아니면 그리지 않음
2. 고무장갑 단서(손가락 모양·접힌 얇은 고무·균일한 인공색)가 2개 이상인가?
                                                    → 다른 Class 로 바꾸지 말고 REVIEW (Class 4)
3. 벌레 단서(부속지·좌우 대칭 몸통·뚜렷한 윤곽)가 2개 이상인가?  → Class 3
4. 나머지 떼어낼 수 있는 물체는 Class 0 / 1 / 2 / 6 중에서 쌍 표로 정한다
5. 쌍 표에서 한쪽이 2개 이상이 아니다               → REVIEW
```

한 객체가 두 곳에 걸치면(예: 잎인지 파인지) 아래 **"애매할 때 구분하는 기준"** 의 단서를 세어서 정하고, 한쪽이 2개 이상이 아니면 REVIEW 입니다.

## Class 0 — 나뭇잎·종이류

**대상**: 조각김치 사이에서 발견되는 나뭇잎 또는 종이 형태의 얇고 납작한 객체

| | |
|---|---|
| 포함 | 나뭇잎, 잘린 잎 조각, 종이 조각(구겨진 것 포함) |
| 제외 | 김치 잎(배추 등 양념이 묻은 잎), 파, 고추 |
| BBox 범위 | 잎 **1장 전체**(잎자루가 붙어 있으면 포함). 종이는 **한 조각 전체**. 겹친 잎은 구분되면 각각 |
| 판단 단서 | 아래 쌍 표의 **0↔6, 0↔2, 0↔1, 김치 잎↔0** 에서 단서를 셉니다 |
| REVIEW | 위 표에서 한쪽이 2개 이상이 아닐 때 → `class_ambiguous` |

## Class 1 — 플라스틱류·돌·금속류

**대상**: 플라스틱, 돌, 금속과 같이 제조 과정에서 이물로 판단되는 단단한 객체

| | |
|---|---|
| 포함 | 플라스틱 조각, 돌, 금속 조각 |
| 제외 | 나뭇가지, 식물성 잎, 파·고추 |
| BBox 범위 | 조각 **1개 전체**. 반짝이는 반사 부분은 객체에 **포함**, 바닥에 생긴 그림자는 **제외** |
| 판단 단서 | 아래 쌍 표의 **2↔1, 0↔1** 에서 단서를 셉니다. (돌·금속은 반사·각진 모서리·인공색·무겁게 눌린 그림자 중 2개 이상) |
| REVIEW | **식물인지 아닌지**가 쌍 표로 정해지지 않을 때 → `class_ambiguous`. 플라스틱·돌·금속 중 무엇인지는 몰라도 됩니다(모두 Class 1) |

## Class 2 — 나뭇가지류

**대상**: 막대 또는 가지 형태의 나무성 이물

| | |
|---|---|
| 포함 | 나뭇가지, 작은 가지 조각, 줄기 형태의 목질 이물 |
| 제외 | 파 줄기, 고추 꼭지, 일반 잎 조각 |
| BBox 범위 | 가지 **1개 전체**. 곁가지가 붙어 있으면 한 가지로 보고 **하나의 BBox**. 서로 떨어진 가지는 각각 |
| 판단 단서 | 아래 쌍 표의 **2↔6, 2↔1, 0↔2** 에서 단서를 셉니다 |
| REVIEW | 위 표에서 한쪽이 2개 이상이 아닐 때 → `class_ambiguous` |

## Class 3 — 벌레류

**대상**: 이미지에서 확인되는 벌레 또는 곤충 형태의 객체

| | |
|---|---|
| 포함 | 벌레, 곤충 형태가 명확한 객체 |
| 제외 | 작은 검은 반점, 김치 양념 덩어리, 형태를 식별할 수 없는 이물 |
| BBox 범위 | **한 마리 전체**. 다리·더듬이·날개가 보이면 **포함**. 여러 마리는 마리마다 각각 |
| 판단 단서 | 아래 **벌레↔반점 표**: 단서 3개(부속지·대칭 몸통·뚜렷한 윤곽) 중 **2개 이상**이면 3. 점·덩어리만 보이면 3 이 아님 |
| REVIEW | 단서 0~1개이고 짧은 변 20px 미만 → `too_small_to_identify` (20px 이상이면 벌레가 아니므로 그리지 않음) |

## Class 4 — 고무장갑 (사용 안 함)

- 교과 7 라벨링에서는 Class 4 를 새로 만들지 않습니다. (프로그램도 새 BBox 생성을 막습니다)
- 기존 TXT 에서 Class 4 가 발견되면 **삭제하거나 다른 Class 로 바꾸지 않고** REVIEW 합니다.
  - 검수표: 상태 `수정 필요` + `발견된 문제` = `REVIEW: Class 4 발견`
- 교차검수자 2명 이상이 확인한 뒤 처리하고, 근거를 `비고(수정 내용)` 에 적습니다.
- 현재 원본 라벨 900장에는 Class 4 가 **없습니다**(점검 결과 0개).

## Class 5 — 병해·갈변

**대상**: 식재료에서 확인되는 병해 또는 갈변 형태

| | |
|---|---|
| 포함 | 갈색으로 변색된 부위, 병해로 판단되는 이상 부위 |
| 제외 | 정상적인 김치 양념 색상, 그림자, 촬영 조명에 의한 색 변화 |
| BBox 범위 | **색이 뚜렷하게 달라지는 경계**까지. **이어진 변색은 한 덩어리 = BBox 1개**, 떨어진 부위는 각각 |
| 여백 | 경계가 번져서 흐리므로 여백 허용치를 **2배**(작은 객체 8px / 10%의 2배=20% / 최대 40px)까지 봐 줍니다 |
| 판단 단서 | 아래 **5↔그림자·양념 표**: 단서 3개(갈·검·누런 색 계열 / 한 곳에 국한된 불규칙 윤곽 / 무르거나 마른 질감 변화) 중 **2개 이상**이면 5. 먼저 "떼어낼 수 있는 물체인가?"를 묻고, 떼어낼 수 있으면 5 가 아닙니다 |
| REVIEW | 단서가 정확히 1개이고 짧은 변 20px 이상이라 갈릴 때 → `class_ambiguous` (0개면 그리지 않음) |

## Class 6 — 파·고추

**대상**: 조각김치 이미지에서 검출 대상으로 지정된 파 또는 고추

| | |
|---|---|
| 포함 | 파 조각, 고추 조각 |
| 제외 | 김치 잎, 나뭇잎, 나뭇가지 |
| BBox 범위 | **조각 1개 전체**. 고추는 꼭지·씨가 붙어 있으면 포함. 파는 흰 줄기부터 잎 끝까지 한 조각 |
| 판단 단서 | 아래 쌍 표의 **0↔6, 2↔6** 에서 단서를 셉니다 |
| REVIEW | 위 표에서 한쪽이 2개 이상이 아닐 때 → `class_ambiguous` |

## 애매할 때 구분하는 기준 (확정) — 단서 세기

헷갈릴 때는 느낌으로 정하지 않고 **눈에 보이는 단서를 셉니다.**

```text
① 아래 쌍 표에서 해당하는 두 Class 를 찾는다
② 단서 3개를 각각 "어느 쪽에 해당하는가" 로 표시한다
③ 2개 이상 해당하는 쪽 = 그 Class        (예: 3개 중 2개가 A → A)
④ 한쪽이 2개 이상이 아니면(1:1, 단서가 안 보임) → REVIEW
```

- 단서는 **사진에서 실제로 보이는 것만** 셉니다. 가려지거나 너무 작아서 안 보이는 단서는 세지 않습니다.
- 3개 중 2개가 같은 쪽이면 **고민하지 말고 그 Class** 로 정합니다. 이 경우는 REVIEW 가 아닙니다.

### 쌍별 단서 표

**나뭇잎·종이(0) ↔ 파·고추(6)**

| 단서 | 0 (잎·종이) | 6 (파·고추) |
|---|---|---|
| 모양 | 납작하고 넓은 면 | 길고 가는 원통(파), 꼭지·씨가 있는 열매(고추) |
| 표면 | 잎맥 무늬 / 종이는 섬유·구김 | 매끈한 원통, 단면이 속 빈 고리(파) / 윤기 있는 껍질(고추) |
| 색 | 마른 갈색·황록색, 종이는 흰색·베이지 | 선명한 연녹·흰색(파), 붉은색·진녹색(고추) |

**나뭇잎·종이(0) ↔ 나뭇가지(2)**

| 단서 | 0 | 2 |
|---|---|---|
| 모양 | 폭이 넓은 면 (길이 ÷ 폭 < 3) | 막대형, 굵기가 거의 일정 (길이 ÷ 폭 ≥ 3) |
| 두께 | 얇아서 그림자가 거의 없음 | 두께가 보이고 아래에 그림자 |
| 표면 | 잎맥·종이 질감 | 나무결·껍질·마디 |

**나뭇가지(2) ↔ 파 줄기(6)**

| 단서 | 2 | 6 |
|---|---|---|
| 색 | 갈색·회색 | 연녹·흰색 |
| 단단함 | 곧거나 각지게 꺾임 | 부드럽게 휘고 늘어짐, 끝에 잎이 갈라짐 |
| 표면 | 껍질·마디·거침 | 매끈, 단면이 속 빈 고리 |

**나뭇가지(2) ↔ 플라스틱·금속 막대(1)**

| 단서 | 2 | 1 |
|---|---|---|
| 색 | 갈색·회색·나무색 | 흰색·파랑 등 인공색, 투명, 금속색 |
| 표면 | 결·껍질, 광택 없음 | 매끈하고 반사·광택 |
| 끝(절단면) | 거칠고 불규칙 | 직선으로 매끈하거나 둥글게 마감 |

**나뭇잎·종이(0) ↔ 플라스틱 조각·비닐(1)**

| 단서 | 0 (종이·잎) | 1 (플라스틱) |
|---|---|---|
| 광택 | 무광 | 빛 반사(하이라이트)가 보임 |
| 가장자리 | 섬유가 풀리거나 찢어진 거친 가장자리 | 매끈하거나 각진 가장자리 |
| 상태 | 양념·물기를 먹어 처지고 구겨짐 | 빳빳하고 모양 유지, 양념이 묻어도 번지지 않음 |

**벌레(3) ↔ 반점·양념 덩어리 (Class 아님)**

| 단서 | 해당하면 벌레 쪽 |
|---|---|
| 부속지 | 다리·더듬이·날개 중 **하나 이상** 확인됨 |
| 몸 | 좌우 대칭의 타원 몸통이나 마디(머리·가슴·배) 구분이 보임 |
| 윤곽 | 주변 양념과 구분되는 **뚜렷한 윤곽선** |

- 2개 이상 → Class 3
- 0~1개이고 짧은 변 **20px 이상** → 벌레가 아니므로 BBox 를 그리지 않는다 (양념 덩어리·반점)
- 0~1개이고 짧은 변 **20px 미만** → 확인이 안 되므로 `REVIEW: too_small_to_identify`

**병해·갈변(5) ↔ 그림자·조명 · 정상 양념 (Class 아님)**

먼저 묻습니다: **"이 물체를 떼어낼 수 있는가?"** 떼어낼 수 있는 물체(잎·조각·벌레 등)면 5 가 아니라 0·1·2·3·6 중 하나입니다. 5 는 식재료 **표면의 색 변화**일 때만 씁니다.

| 단서 | 해당하면 5 (병해·갈변) 쪽 |
|---|---|
| 색 계열 | **갈색·검은색·누런색** 계열 (붉은 양념 색은 정상) |
| 위치·형태 | 식재료의 한 곳에 **국한**되고 윤곽이 불규칙 (사진 한쪽 전체가 어두운 것은 조명) |
| 질감 | 주변보다 무르거나 마른 **질감 변화**가 보임 (그림자는 질감이 그대로) |

- 2개 이상 → Class 5
- 0~1개 → 그리지 않는다 (그림자·조명·정상 양념). 단 짧은 변이 20px 이상이고 단서가 정확히 1개라서 판단이 갈리면 `REVIEW: class_ambiguous`

**김치 잎 ↔ 나뭇잎(0)** (김치 잎이면 그리지 않음)

| 단서 | 해당하면 김치 잎 (그리지 않음) 쪽 |
|---|---|
| 양념 | 붉은 양념이 **묻어 있거나 스며 있음** |
| 두께 | 두껍고 흰 줄기(심)가 있음 |
| 위치·결 | 김치 무더기 속에서 같은 질감으로 이어짐 |

- 2개 이상 → 김치 잎, BBox 를 그리지 않는다
- 그 외 → 나뭇잎(Class 0)

**고무장갑처럼 보이는 것 (Class 4)**

| 단서 | 해당하면 Class 4 후보 |
|---|---|
| 모양 | 손가락 모양 또는 손목 입구가 있는 형태 |
| 재질 | 넓고 얇은 고무가 접히고 늘어진 모양, 균일한 광택 |
| 색 | 균일한 인공색 (노랑·분홍·파랑·주황 등) |

- 2개 이상 → **Class 1 이나 다른 Class 로 바꾸지 말고** `REVIEW: Class 4 발견`
- 기존 TXT 에 이미 Class 4 가 있으면 단서와 상관없이 삭제하지 않고 같은 REVIEW

### 여러 단서가 섞일 때의 순서

1. **떼어낼 수 있는 물체인가?** 아니면 표면의 색 변화 → 5 쌍 표
2. 물체라면 위의 **쌍 표** 로 단서를 센다 (2개 이상 한쪽 → 그 Class)
3. 같은 위치에 서로 다른 물체가 붙어 있으면 **각각 따로 BBox** (하나로 합쳐서 Class 를 고르지 않는다)
4. 어느 쪽도 2개가 안 되면 REVIEW

## REVIEW 로 보내는 조건 (이 중 하나일 때만)

| 조건 | 이유 코드 |
|---|---|
| 쌍 표에서 **한쪽이 2개 이상이 아님** (1:1, 또는 단서가 안 보임) | `class_ambiguous` |
| 짧은 변 **20px 미만**이면서 단서가 부족해 무엇인지 모름 | `too_small_to_identify` |
| 가려져서 단서를 셀 수 없음 | `occlusion_ambiguous` |
| BBox 경계를 정할 수 없음 | `bbox_boundary_ambiguous` |
| 붙어 있는 객체를 나눌 수 없음 | `object_separation_ambiguous` |
| Class 4 단서 2개 이상 또는 기존 라벨에 Class 4 | `REVIEW: Class 4 발견` |

REVIEW 가 **아닌** 경우 — 고민하지 말고 정합니다.
- 세부 모양이 다를 뿐 Class 는 확실한 경우 (플라스틱인지 돌인지 몰라도 식물이 아님이 확실 → 둘 다 Class 1)
- 쌍 표에서 한쪽이 2개 이상인 경우
- 벌레 단서가 0~1개이고 20px 이상 (벌레가 아니므로 그리지 않음)

REVIEW 처리 방법: 상태 `수정 필요` + `발견된 문제` = `REVIEW: 이유 코드`, 어떤 단서가 어떻게 갈렸는지 한 줄을 `비고(수정 내용)` 에 적습니다. (프로그램: 사진에서 `R` 키)
예) `REVIEW: class_ambiguous` / 비고: `잎↔파: 모양=파, 표면=불명, 색=잎 → 1:1`

## 작업 흐름

```text
객체 발견
        ↓
위 순서와 Class 별 표에서 Class 확인
        ↓
명확함 → BBox 작성(BBox 기준서) + Class 지정
애매함 → 임의로 지정하지 않고 REVIEW → 교차검수자가 최종 확인
```

## 결정 사항과 변경 이력

- 위 Class 별 포함·제외·BBox 범위·여백·REVIEW 조건은 **확정 기준**입니다. 대표 예시는 실제 사진이 회사 데이터라 이 저장소에 싣지 않고 팀 내부 자료로만 보관합니다.
- 기준을 바꾸려면 이 문서의 해당 Class 표만 고치고 아래에 적습니다.
