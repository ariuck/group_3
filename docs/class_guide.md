# Class Labeling Guide

> 라벨링할 때 **"이 객체를 몇 번 Class 로 저장해야 하는가?"** 를 팀원 모두가 같은 기준으로 판단하기 위한 문서입니다.
> 이 기준은 900장 검수와 교차검수에 그대로 적용합니다. 프로그램의 Class 설정은 `configs/classes.yaml` 입니다.
> BBox 를 어디까지 그리는지는 [bbox_guide.md](bbox_guide.md), 검수표 작성은 [manifest_guide.md](manifest_guide.md) 를 봅니다.

## 공통 원칙

- 사용 Class: 0~6 (번호를 바꾸지 않는다). **Class 4 는 사용하지 않는다.**
- 김치 자체는 검출 대상 Class 가 아닙니다. 김치에는 BBox 를 그리지 않습니다.
- 정상 김치 / 김치+대상 / 대상 단독 은 **이미지 유형**이지 Class 가 아닙니다.
- **한 객체 = BBox 1개 = Class 1개**입니다. 한 BBox 에 두 Class 를 섞지 않습니다.
- Class 는 **재질·형태가 눈으로 확인될 때만** 지정합니다. 확인할 단서가 없으면 추측하지 않고 REVIEW 입니다.
- 객체가 서로 다른 Class 와 겹쳐 있어도 각각 따로 BBox 를 그립니다.

## Class 한눈에 보기

| ID | 이름 | 한 줄 기준 | 한 BBox 의 단위 | 실제 라벨의 크기(짧은 변 중앙값) |
|---:|---|---|---|---:|
| 0 | 나뭇잎·종이류 | 납작하고 얇은 **잎 또는 종이** 조각 | 잎 1장 / 종이 1조각 | 약 200px |
| 1 | 플라스틱류·돌·금속류 | 식물이 아닌 **단단한 이물** (플라스틱·돌·금속) | 조각 1개 | 약 154px |
| 2 | 나뭇가지류 | **목질(나무)** 의 막대·가지 | 가지 1개 (곁가지 포함) | 약 185px |
| 3 | 벌레류 | **곤충·벌레**의 몸 형태가 확인되는 것 | 한 마리 | 약 100px |
| 4 | 고무장갑 | **사용 안 함** → 발견되면 REVIEW | – | – |
| 5 | 병해·갈변 | 식재료가 **변색·병든 부위** | 이어진 변색 덩어리 1개 | 약 125px |
| 6 | 파·고추 | **파 또는 고추** 조각 | 조각 1개 | 약 125px |

> 크기는 참고입니다. 실제 라벨 4399개를 집계한 값이며, 이보다 아주 작거나 큰 BBox 는 한 번 더 확인합니다.
> (이미지는 4848×2704, BBox 의 짧은 변 전체 중앙값 약 150px)

## 어떤 Class 인지 정하는 순서

```text
1. 김치(양념·김치 잎)인가?                      → 예: BBox 를 그리지 않는다
2. 살아 있는 벌레·곤충 형태인가?                 → 예: Class 3
3. 식물이 아닌 단단한 물체(플라스틱·돌·금속)인가? → 예: Class 1
4. 나무처럼 단단하고 막대·가지 모양인가?          → 예: Class 2
5. 납작하고 얇은 잎·종이인가?                    → 예: Class 0
6. 파 또는 고추인가?                            → 예: Class 6
7. 식재료 표면의 변색·병든 부위인가?              → 예: Class 5
8. 고무장갑처럼 보이는가?                        → 예: 삭제하지 말고 REVIEW (Class 4)
9. 위 어디에도 확실히 들어가지 않는다             → REVIEW
```

한 객체가 두 곳에 걸치면(예: 잎인지 파인지) 아래 "헷갈리는 쌍"의 단서로 정하고, 단서가 없으면 REVIEW 입니다.

## Class 0 — 나뭇잎·종이류

**대상**: 조각김치 사이에서 발견되는 나뭇잎 또는 종이 형태의 얇고 납작한 객체

| | |
|---|---|
| 포함 | 나뭇잎, 잘린 잎 조각, 종이 조각(구겨진 것 포함) |
| 제외 | 김치 잎(배추 등 양념이 묻은 잎), 파, 고추 |
| BBox 범위 | 잎 **1장 전체**(잎자루가 붙어 있으면 포함). 종이는 **한 조각 전체**. 겹친 잎은 구분되면 각각 |
| 판단 단서 | 잎맥이 보이거나 얇게 펴진 모양 → 0. 양념이 두껍게 묻고 김치와 같은 색·질감 → 김치 잎(그리지 않음) |
| REVIEW | 나뭇잎인지 김치 잎인지 단서가 없을 때 → `class_ambiguous` |

## Class 1 — 플라스틱류·돌·금속류

**대상**: 플라스틱, 돌, 금속과 같이 제조 과정에서 이물로 판단되는 단단한 객체

| | |
|---|---|
| 포함 | 플라스틱 조각, 돌, 금속 조각 |
| 제외 | 나뭇가지, 식물성 잎, 파·고추 |
| BBox 범위 | 조각 **1개 전체**. 반짝이는 반사 부분은 객체에 **포함**, 바닥에 생긴 그림자는 **제외** |
| 판단 단서 | 반사·광택, 각진 모서리, 인공적인 색(파랑·흰색 등) → 1 |
| REVIEW | 재질(플라스틱/돌/금속 중 무엇인지가 아니라 **식물인지 아닌지**)도 판단이 안 될 때 → `class_ambiguous` (셋 중 어느 것이든 Class 1 이므로 세부 재질을 몰라도 되는 경우는 REVIEW 가 아닙니다) |

## Class 2 — 나뭇가지류

**대상**: 막대 또는 가지 형태의 나무성 이물

| | |
|---|---|
| 포함 | 나뭇가지, 작은 가지 조각, 줄기 형태의 목질 이물 |
| 제외 | 파 줄기, 고추 꼭지, 일반 잎 조각 |
| BBox 범위 | 가지 **1개 전체**. 곁가지가 붙어 있으면 한 가지로 보고 **하나의 BBox**. 서로 떨어진 가지는 각각 |
| 판단 단서 | 단단하고 갈색·회색, 마디·껍질 질감 → 2. 부드럽고 녹색·흰색, 속이 비어 보임 → 파(Class 6) |
| REVIEW | 나뭇가지와 채소 줄기 구분이 안 될 때 → `class_ambiguous` |

## Class 3 — 벌레류

**대상**: 이미지에서 확인되는 벌레 또는 곤충 형태의 객체

| | |
|---|---|
| 포함 | 벌레, 곤충 형태가 명확한 객체 |
| 제외 | 작은 검은 반점, 김치 양념 덩어리, 형태를 식별할 수 없는 이물 |
| BBox 범위 | **한 마리 전체**. 다리·더듬이·날개가 보이면 **포함**. 여러 마리는 마리마다 각각 |
| 판단 단서 | 몸통 + 다리/더듬이/날개 중 **하나 이상이 확인**되어야 3. 점·덩어리만 보이면 3 이 아님 |
| REVIEW | 벌레인지 단순 얼룩인지 판단이 안 될 때 → `too_small_to_identify` (작을 때) 또는 `class_ambiguous` |

## Class 4 — 고무장갑 (사용 안 함)

- 교과 7 라벨링에서는 Class 4 를 새로 만들지 않습니다. (프로그램도 새 BBox 생성을 막습니다)
- 기존 TXT 에서 Class 4 가 발견되면 **삭제하거나 다른 Class 로 바꾸지 않고** REVIEW 합니다.
  - 검수표: 상태 `수정 필요` + `발견된 문제` = `REVIEW: Class 4 발견`
- 교차검수자 2명 이상이 확인한 뒤 처리하고, 근거를 `비고(수정 내용)` 에 적습니다.
- 현재 원본 라벨 900장에는 Class 4 가 **없습니다**(점검 결과 0개).

## Class 5 — 병해·갈변

**대상**: 식재료에서 확인되는 병해 또는 갈변 형태

| | |
|---|---|
| 포함 | 갈색으로 변색된 부위, 병해로 판단되는 이상 부위 |
| 제외 | 정상적인 김치 양념 색상, 그림자, 촬영 조명에 의한 색 변화 |
| BBox 범위 | **색이 뚜렷하게 달라지는 경계**까지. **이어진 변색은 한 덩어리 = BBox 1개**, 떨어진 부위는 각각 |
| 여백 | 경계가 번져서 흐리므로 여백 허용치를 **2배**(작은 객체 8px / 10%의 2배=20% / 최대 40px)까지 봐 줍니다 |
| 판단 단서 | 같은 식재료 안에서 주변과 색·질감이 다르고 모양이 식재료를 따라간다 → 5. 한쪽 방향으로 번지는 밝기 차이·그림자 모양 → 조명 |
| REVIEW | 갈변인지 조명 차이인지 판단이 안 될 때 → `class_ambiguous` |

## Class 6 — 파·고추

**대상**: 조각김치 이미지에서 검출 대상으로 지정된 파 또는 고추

| | |
|---|---|
| 포함 | 파 조각, 고추 조각 |
| 제외 | 김치 잎, 나뭇잎, 나뭇가지 |
| BBox 범위 | **조각 1개 전체**. 고추는 꼭지·씨가 붙어 있으면 포함. 파는 흰 줄기부터 잎 끝까지 한 조각 |
| 판단 단서 | 길고 속이 비어 둥근 단면(파), 윤기 있는 붉은/녹색 껍질과 씨(고추) → 6. 납작하고 잎맥(잎) → 0 |
| REVIEW | 파·고추와 다른 식물 조각이 구분이 안 될 때 → `class_ambiguous` |

## 헷갈리는 쌍 — 이렇게 정합니다

| 헷갈리는 것 | 정하는 기준 | 단서가 없으면 |
|---|---|---|
| 나뭇잎(0) ↔ 파(6) | 납작·잎맥 → 0 / 길고 둥글며 속이 빈 줄기 → 6 | REVIEW |
| 나뭇가지(2) ↔ 파 줄기(6) | 단단·갈색·껍질 → 2 / 부드럽고 녹색·흰색 → 6 | REVIEW |
| 나뭇가지(2) ↔ 플라스틱 막대(1) | 나무결·갈색 → 2 / 매끈·인공색 → 1 | REVIEW |
| 벌레(3) ↔ 검은 반점 | 다리·더듬이·날개 중 하나 이상 확인 → 3 / 점·덩어리 → 그리지 않음 | REVIEW |
| 갈변(5) ↔ 그림자·조명 | 식재료를 따라 색이 변함 → 5 / 한쪽으로 번지는 밝기 차 → 그리지 않음 | REVIEW |
| 고무장갑처럼 보임 | 무조건 Class 4 로 만들지 않고 | REVIEW (삭제 금지) |

## REVIEW 로 보내는 조건 (이 중 하나면 REVIEW)

1. 위 표의 단서로도 **두 Class 중 하나를 고를 수 없을 때**
2. 객체가 **짧은 변 20px 미만**이면서 무엇인지 알 수 없을 때 (`too_small_to_identify`)
3. 가려져서 Class 를 정할 수 없을 때 (`occlusion_ambiguous`)
4. Class 4 가 있을 때

REVIEW 가 **아닌** 경우: 세부 모양이 다를 뿐 Class 는 확실한 경우(예: 플라스틱인지 돌인지 몰라도 식물이 아님이 확실하면 둘 다 Class 1). 이때는 고민하지 말고 지정합니다.

REVIEW 처리 방법: 상태 `수정 필요` + `발견된 문제` = `REVIEW: 이유 코드`, 이유 한 줄을 `비고(수정 내용)` 에 적습니다. (프로그램: 사진에서 `R` 키)

## 작업 흐름

```text
객체 발견
        ↓
위 순서와 Class 별 표에서 Class 확인
        ↓
명확함 → BBox 작성(BBox 기준서) + Class 지정
애매함 → 임의로 지정하지 않고 REVIEW → 교차검수자가 최종 확인
```

## 결정 사항과 변경 이력

- 위 Class 별 포함·제외·BBox 범위·여백·REVIEW 조건은 **확정 기준**입니다. 대표 예시는 실제 사진이 회사 데이터라 이 저장소에 싣지 않고 팀 내부 자료로만 보관합니다.
- 기준을 바꾸려면 이 문서의 해당 Class 표만 고치고 아래에 적습니다.

| 날짜 | 바꾼 내용 | 이유 |
|---|---|---|
