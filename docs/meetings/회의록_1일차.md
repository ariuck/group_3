
# 1일차 회의록 — 데이터 이해 · 기준선 · 설계 · 첫 End-to-End



## 1. 오늘의 목표
데이터와 보안을 확인하고, 팀 기준선을 정하고, 만들 프로그램을 설계한 뒤, **사진 1장으로 열기 → 저장 → 다시 불러오기**까지 한 번 돌려 본다.

## 2. 논의하고 정한 것

| 주제     | 결정                                                                              |
| ------ | ------------------------------------------------------------------------------- |
| 데이터 보안 | 회사 제공 데이터(NDA)는 Git 에 올리지 않는다. 코드·문서·Manifest·보고서만 올린다                          |
| 데이터 구조 | RAW(원본, 읽기만) → WORK(수정) → FINAL(최종). RAW 에는 저장하지 않는다                            |
| 전체 규모  | 900장 = 학습데이터1/train 500 · 학습데이터2/train 220 · 학습데이터2/validation 180              |
| Class  | 0~6 그대로, 번호 바꾸기 금지, **Class 4 는 사용하지 않음**(발견 시 삭제하지 않고 REVIEW). 김치는 Class 가 아니다 |
| BBox   | 5가지 약속(전체 포함·경계에 가깝게·객체마다 따로·작아도 누락 금지·애매하면 REVIEW)                             |
| 정상 김치  | 빈 TXT 는 오류가 아니라 정답일 수 있다. 정상 김치·대상 단독 사진도 지우지 않는다                               |
| 작업 분담  | 5명이 각 180장. 교차검수는 1→2→3→4→5→1 순환(작업자와 검수자는 달라야 함)                               |
| 좌표 약속  | BBox 는 **원본 이미지 픽셀 좌표**로 기억하고 화면에 그릴 때만 배율을 곱한다                                 |
| Git 규칙 | 기능 하나 → 직접 실행 → 커밋. 메시지는 `feat:`/`fix:`/`docs:`/`test:`/`chore:` + 무엇을 바꿨는지     |

### 검수표(Manifest) 결정 — 초안에서 바뀐 점
1일차 초안(`manifest.csv` 14칸, PENDING/PASS/EDITED …)을 **팀이 확정한 검수표 틀**로 바꿨다. 최종 기준이 우선한다.

- 파일: `manifests/dataset_manifest.xlsx`(시트 `검수표` + `Class 기준`), CSV 는 `dataset_manifest.csv`
- 칸: 14 → 17 → **19칸**(맨 끝에 `출처 데이터셋`·`원래 split` 추가)
- 상태: `검수 전 / 검수 완료 / 수정 필요 / 수정 완료 / 제외`
- REVIEW 표시: `상태 = 수정 필요` + `발견된 문제 = REVIEW: 이유 코드`
- 프로그램이 저장할 때 자동으로 채우는 칸과 **사람이 채우는 칸**을 구분했다 (`manifest_guide.md`)

## 4. 막혔던 점과 해결 (`1일차_과정기록.md`)

| 막힌 점 | 원인 | 해결 |
|---|---|---|
| BBox 를 선택·추가하면 프로그램이 멈춤 | 목록을 다시 그리면 "선택됨" 신호가 또 발생해 무한 반복 | 이미 선택된 항목이면 신호 무시 |
| 휠·드래그가 느림 | 4K 원본 전체를 매번 줄여서 그림 | 이미지(무거움)와 BBox(가벼움)를 따로 그리고 줄인 이미지를 재사용 |
| 터미널에서 `python` 실행 안 됨 | PATH 에 Python 없음 | `py` 명령 사용 |
