# 교과 7 · 1일차 — 6. 라벨링 프로그램 설계 ① Must Have 기능 목록

> 프로젝트: 조각김치 이물검출 라벨링 (JPG 900장 + YOLO TXT 900개, Class 0~6)
> 방식: **기존 TXT 를 불러와 사람이 검수·보정**하는 프로그램 (빈 이미지를 처음부터 라벨링하지 않음)
> 작성 목적: 2일차부터 "무엇을, 어디까지, 어떤 순서로" 만들지 팀이 같은 기준을 갖기 위함

---

## 1. 범위를 나누는 기준

| 구분 | 의미 | 원칙 |
|---|---|---|
| **Must Have** | 없으면 900장을 **안전하게 검수·보정할 수 없는** 기능 | 반드시 완성. 하나라도 빠지면 본 작업 시작 불가 |
| **Should Have** | 있으면 작업 속도·품질이 크게 좋아지는 기능 | Must 가 안정된 뒤 시간이 있으면 |
| **Optional** | 없어도 프로젝트 목표 달성에 지장 없는 기능 | 핵심이 안정된 뒤에만 |

> 판단 질문: **"이 기능이 없으면 라벨이 틀어지거나, 작업이 유실되거나, 검수를 못 하는가?"** → 그렇다면 Must.

## 5. 이번 프로젝트에서 **하지 않는 것**

- 새로운 Class 추가(정상 김치 = Class 7 같은 것). Class 는 회사 제공 **0~6 만** 사용
- Class ID 재번호(5→4, 6→5). 그대로 유지
- 기존 `train / validation` 재분할, Dataset 1·2 단순 합치기 (교과 8 에서 결정)
- 정상 김치·객체 단독 이미지의 임의 삭제
- RAW 폴더 직접 수정, 데이터를 코드와 같은 공개 저장소에 올리는 것

## 6. 구현 순서 (작은 기능 → 실행 → 확인 → 다음)

```
[1일차]  이미지 1장 End-to-End
         열기 → TXT Load → BBox 표시 → 추가/삭제/Class → WORK 저장 → Reload 복원
         (M01·02·05·08~15·19·20·22·25 의 최소 버전)

[2일차]  라벨링 도구 완성
         이전/다음, Zoom/Pan, 검수 상태·메모·작업자, 저장 후 다음, 미저장 경고, Undo
         (M03·04·06·07·16~18·21 + Should 일부)  →  Golden Sample 10~20장 검증

[3일차]  안정화 · Validation · Manifest · Pilot Test(20~50장)
         (M23·24)  →  Pilot 통과해야 본 작업 시작

[4~5일차] 900장 전수 검수 · 교차검수 · 최종 QA · FINAL · 교과 8 인계
```

> 좌표·저장 오류가 남아 있으면 **다음 단계로 넘어가지 않는다.**

## 7. 기능 하나를 만들기 전에 적는 4가지 (예시 3개)

| 질문 | M08 기존 TXT 자동 Load | M10 새 BBox 작성 | M19 저장 |
|---|---|---|---|
| **입력은?** | JPG 경로 | 마우스 누름 · 드래그 · 뗌 좌표 | BBox 목록(원본 픽셀), 이미지 크기 |
| **무엇을 하나?** | 같은 이름 TXT 를 찾아 읽고 비율값 → 픽셀로 변환 | 화면 좌표 → 원본 좌표 변환, 범위 보정, Class 연결 | 픽셀 → YOLO 비율값 변환 후 WORK 에 기록 |
| **결과는?** | BBox 목록 + 화면 표시 | BBox 목록에 1개 추가, 선택 상태 | `class xc yc w h` 줄들이 든 TXT |
| **실패는 어떻게 아나?** | TXT 없음 / 빈 TXT / 형식 오류 줄 → 상태줄·경고로 알림 | 5px 미만 드래그 · 이미지 밖 → 만들지 않고 안내 | 쓰기 실패 → 오류창, **이동하지 않고 화면 유지** |
