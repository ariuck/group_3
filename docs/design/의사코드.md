# 교과 7 · 1일차 — 6. 라벨링 프로그램 설계 ② 의사 코드 (이미지 1장 End-to-End)

> 대상 프로그램: `main.py` → `src/ui/main_window.py` (기능별 코드: `src/yolo`, `src/bbox`, `src/validation`)
> 읽는 방법: 위에서 아래로 `↓` 를 따라가면 프로그램이 실제로 움직이는 순서입니다.

---

## 1. 프로그램 전체 흐름 (1일차 End-to-End)

```text
이미지를 열면 같은 이름의 TXT 를 찾을 수 있는가?
        ↓
TXT 의 비율값을 원본 픽셀 좌표로 바꿔 BBox 로 기억하는가?
        ↓
기억한 BBox 를 화면 배율에 맞춰 이미지 위에 그리는가?
        ↓
사람이 추가 · 삭제 · Class 변경을 할 수 있는가?
        ↓
수정한 BBox 를 YOLO 비율값으로 되돌려 WORK 에 저장하는가?
        ↓
다시 불러왔을 때 같은 위치에 BBox 가 복원되는가?
```

> **핵심 약속 한 줄**
> BBox 는 항상 **원본 이미지 픽셀 좌표**로만 기억하고, 화면에 그릴 때만 배율을 곱하며, 저장할 때만 YOLO 비율값으로 바꾼다.

---

## 2. 프로그램이 기억하는 값 (변수)

| 변수 | 의미 |
|---|---|
| `image_path`, `pil_image`, `img_w`, `img_h` | 열려 있는 이미지와 원본 크기 |
| `boxes` | `[{cls, x1, y1, x2, y2}, ...]` — **원본 픽셀 좌표** |
| `selected` | 선택된 BBox 번호 (없으면 None) |
| `current_class` | 새 BBox 를 만들 때 쓸 Class |
| `dirty` | 저장하지 않은 변경이 있는가 |
| `scale`, `offset_x`, `offset_y` | 화면 표시용 배율과 위치 |

공통 약속: Class 는 회사 제공 **0~6** 그대로, **Class 4 는 사용 안 함**, 저장은 **WORK 에만**(RAW 는 읽기 전용).

## 3. 프로그램 시작

```text
프로그램 실행
        ↓
기억할 변수 준비
(boxes, selected, current_class, dirty, scale ...)
        ↓
화면 부품 배치
(버튼줄 · Canvas · 클래스 목록 · 라벨 목록 · 상태줄)
        ↓
이벤트 연결
(마우스 누름/드래그/뗌/이동 · 키보드 · 목록 선택)
        ↓
"이미지를 열어 주세요" 안내 표시
        ↓
mainloop — 사용자 입력을 계속 기다림
```

## 4. 이미지 열기

```text
[이미지 열기] 클릭
        ↓
저장 안 한 변경이 있는가?
        ├─ 예  → 저장할까요? (예 / 아니오 / 취소)
        │          └─ 취소 → 여기서 중단
        └─ 아니오
        ↓
파일 선택창에서 JPG 선택
        ↓
선택을 취소했는가?
        ├─ 예  → 중단
        └─ 아니오
        ↓
이미지를 실제로 읽어 보기
        ├─ 실패(깨진 파일) → 오류창만 띄우고 프로그램은 계속 실행
        └─ 성공
        ↓
원본 이미지와 가로·세로 크기 기억
        ↓
TXT 읽기 (다음 단계)
        ↓
화면 표시
```

---

## 5. TXT 찾기 · 읽기

```text
WORK 폴더에 내가 저장한 TXT 가 있는가?
        ├─ 예  → 그것을 사용 (지난번 작업 이어서)
        └─ 아니오
                ↓
        경로의 images 를 labels 로 바꿔 RAW TXT 찾기
                ↓
        같은 폴더에서도 찾기
                ↓
        끝까지 못 찾음 → "TXT 없음, 이미지를 직접 확인" 안내 후 BBox 없이 시작
        ↓
TXT 를 한 줄씩 읽기
        ↓
빈 줄인가?  → 건너뜀
        ↓
5개 항목이고 숫자로 바뀌는가?
        ├─ 아니오 → 읽지 못한 줄 +1 (몰래 버리지 않고 개수를 알려 줌)
        └─ 예
        ↓
class, 중심x, 중심y, 폭, 높이 (0~1 비율값)
        ↓
원본 픽셀 좌표로 변환
x1 = (중심x − 폭/2) × 이미지 가로
        ↓
boxes 에 추가
        ↓
전부 읽었는데 BBox 가 0개인가?
        └─ 오류가 아님 → "빈 TXT: 이물이 정말 없는지 확인" 안내
```

> 빈 TXT 는 **정상 김치 이미지(이물 없음)** 일 수 있으므로 오류로 처리하지 않습니다.

## 6. 화면에 그리기 (이미지와 BBox 를 따로)

```text
이미지를 그리는가? (무거움 — 열 때 / 창 크기 바뀔 때만)
        ↓
배율 = 캔버스에 전체가 들어가는 비율
        ↓
캔버스 가운데에 오도록 시작 위치(offset) 계산
        ↓
원본을 배율만큼 줄여서 Canvas 에 그림
        ↓
줄인 이미지를 변수에 붙들어 둠 (안 그러면 화면에서 사라짐)
```

```text
BBox 를 그리는가? (가벼움 — 바뀔 때마다)
        ↓
이전 BBox 만 지움 (이미지는 그대로)
        ↓
원본 좌표 → 화면 좌표
화면 = 원본 × 배율 + offset
        ↓
Class 색으로 사각형 + 이름표
        ↓
선택된 BBox 는 노란색 굵은 선
```

```text
창 크기를 바꾸는 동안 (이벤트가 수십 번 발생)
        ↓
이미 예약된 다시그리기가 있으면 취소
        ↓
0.1초 뒤 한 번만 이미지 다시 그리기 예약  (디바운스)
```

> 이미지와 BBox 를 한꺼번에 다시 그리면 마우스를 움직일 때마다 4K 이미지를 줄이게 되어 **렉**이 걸립니다.

## 7. 마우스로 BBox 만들기

```text
마우스를 누름
        ↓
시작 위치 기억 + 점선 임시 사각형 생성
        ↓
누른 채 움직임
        ↓
임시 사각형을 마우스 위치까지 늘림
        ↓
마우스를 뗌
        ↓
임시 사각형 삭제
        ↓
가로·세로 이동이 모두 5px 미만인가?
        ├─ 예 (클릭) → 그 위치의 BBox 선택 (없으면 선택 해제) → 끝
        └─ 아니오
        ↓
한쪽만 5px 미만인가?
        ├─ 예 (얇은 실수 드래그) → 안내만 하고 만들지 않음 → 끝
        └─ 아니오
        ↓
화면 좌표를 원본 픽셀 좌표로 변환
원본 = (화면 − offset) ÷ 배율
        ↓
이미지 밖으로 나간 부분은 잘라냄 (0 ~ 이미지 크기)
        ↓
왼쪽 < 오른쪽, 위 < 아래 가 되도록 정렬
        ↓
원본 기준 4px 미만인가?  → 만들지 않음
        ↓
현재 Class 가 4 (사용 안 함) 인가?  → 경고만 하고 만들지 않음
        ↓
boxes 에 추가 + 방금 만든 BBox 를 선택
        ↓
저장 안 함 표시(*) + 화면·목록 갱신
```

---

## 8. 선택 · 삭제 · Class 변경

```text
BBox 선택
        ↓
클릭한 위치를 원본 좌표로 변환
        ↓
그 점을 포함하는 BBox 후보 찾기
        ↓
겹쳐 있으면 면적이 가장 작은(안쪽) BBox 선택
        ↓
Class 목록도 그 BBox 의 Class 로 맞춤
```

```text
삭제 (Delete 키 / 버튼)
        ↓
선택된 BBox 가 있는가?
        ├─ 아니오 → "먼저 BBox 를 선택하세요"
        └─ 예 → boxes 에서 제거 → 선택 해제 → 변경 표시(*)
```

```text
Class 변경 (숫자키 0~6 / 목록 클릭)
        ↓
선택한 Class 가 4 인가?  → 경고 후 원래 Class 로 되돌림
        ↓
BBox 가 선택되어 있는가?
        ├─ 예   → 그 BBox 의 Class 를 변경 (기존 라벨의 Class 오류 수정)
        └─ 아니오 → 앞으로 새로 그릴 BBox 의 Class 로만 사용
```

---

## 9. 저장

```text
[저장] / Ctrl+S
        ↓
boxes 의 원본 픽셀 좌표를 YOLO 비율값으로 변환
x중심 = (x1 + x2) / 2 ÷ 이미지 가로
        ↓
"class 중심x 중심y 폭 높이" 줄 만들기 (소수 10자리)
        ↓
WORK 폴더가 없으면 만들기
        ↓
WORK 에 TXT 기록  (RAW 는 절대 건드리지 않음)
        ↓
저장 성공?
        ├─ 아니오 → 오류창 + 이동하지 않고 현재 화면 유지
        └─ 예 → 저장 안 함 표시(*) 해제 + "저장 완료" 안내
```

BBox 가 0개면 **빈 TXT** 가 저장됩니다. (정상 김치 이미지의 정답이 될 수 있음)

## 10. 다시 불러오기 (1일차 성공 기준)

```text
저장 완료
        ↓
[다시 불러오기] 클릭
        ↓
WORK 의 TXT 를 다시 읽음 (비율 → 픽셀)
        ↓
같은 위치에 같은 Class 의 BBox 가 나타나는가?
        ├─ 예  → 성공: 좌표 변환과 저장이 올바름
        └─ 아니오 → 변환식(비율 ↔ 픽셀) 또는 offset/배율 계산을 먼저 점검
```

## 11. 작업 유실 방지 · 종료

```text
이미지를 바꾸려 하거나 창을 닫으려 함
        ↓
저장 안 한 변경이 있는가?
        ├─ 아니오 → 그대로 진행
        └─ 예 → "저장할까요?" (예 / 아니오 / 취소)
                  ├─ 예     → 저장 성공 시에만 진행 (실패하면 머무름)
                  ├─ 아니오 → 변경을 버리고 진행
                  └─ 취소   → 머무름
```

## 12. 한 장 요약

```text
BBox 는 항상 "원본 이미지 픽셀 좌표" 로만 기억한다
        ↓
화면에 그릴 때만 배율을 곱한다
        ↓
마우스 입력은 받는 즉시 배율로 나눠서 원본 좌표로 되돌린다
        ↓
저장할 때만 YOLO 비율값으로 바꾼다
        ↓
그래서 창 크기 · 확대 비율이 바뀌어도 BBox 는 같은 객체 위치에 남는다
```

## 13. 함수 ↔ 의사 코드 대응표 (코드 찾기용)

| 의사 코드 단계 | 코드의 함수 |
|---|---|
| 프로그램 시작 | `main()`, `build_widgets()`, `bind_events()` |
| 이미지 열기 | `open_image()` |
| TXT 찾기 · 읽기 | `find_label_path()`, `load_boxes()`, `read_yolo_file()` |
| 화면에 그리기 | `show_image()`, `draw_boxes()`, `on_canvas_resize()` |
| 좌표 변환 | `to_screen()`, `to_image()`, `yolo_to_pixel()`, `pixel_to_yolo()` |
| 마우스로 BBox 만들기 | `on_mouse_down()`, `on_mouse_drag()`, `on_mouse_up()` |
| 선택 · 삭제 · Class | `find_box_at()`, `select_box()`, `delete_selected()`, `choose_class()` |
| 저장 | `save()`, `write_yolo_file()` |
| 다시 불러오기 | `reload()` |
| 작업 유실 방지 | `confirm_discard()`, `on_close()` |
