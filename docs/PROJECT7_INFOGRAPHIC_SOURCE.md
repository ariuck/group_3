## 1. 프로젝트 개요 & 핵심 목표 (Project Overview)

- **프로젝트 명**: 조각김치 이물검출 Ground Truth 데이터셋 구축 및 무결성 검수 파이프라인 (교과 7)
- **배경 및 목적**: 
  - 딥러닝 기반 객체검출(교과 8 YOLO11n)과 실시간 제조공정 검사 시스템(교과 14 Jetson)의 성공 여부는 정제된 학습 데이터의 품질에 직결됨 ("Garbage In, Garbage Out").
  - 산업 현장과 유사하게 가상 생성된 4K 고해상도 조각김치 데이터 900장을 대상으로, 기존 불완전한 YOLO 라벨을 정밀 검수·수정·보완하고 전수 검증을 거쳐 **무결점(Defect 0건) FINAL 데이터셋**을 완성함.
- **핵심 역할**:
  1. 전용 라벨링 도구(Tkinter GUI v1/v2) 자체 개발 및 직관적 편집 환경 제공
  2. 3단계 데이터 생명주기(RAW 불변 $\rightarrow$ WORK 수정 $\rightarrow$ FINAL 확정) 격리 체계 구축
  3. 19개 지표 기반 Manifest 검수 대장 및 전수 교차검수(작성자 $\neq$ 검수자) 제도 운용
  4. 엄격한 규칙 기반 Validation 모듈을 통한 무결성 보증

### (2) 이물 검출 클래스 정의 (Class ID 0 ~ 6)
| Class ID | 클래스 명 | 대상 설명 및 특이사항 |
|:---:|:---|:---|
| **0** | 나뭇잎·종이류 | 배춧잎 이외의 이물성 잎사귀, 종이 조각 |
| **1** | 플라스틱류·돌·금속류 | 포장재 비닐, 플라스틱 파편, 결석, 나사 등 경질 이물 |

| **3** | 벌레류 | 벌레 사체, 유충 등 생물학적 위해 요소 |
| **4** | 고무장갑 | **현재 비활성화(사용 안 함)** - 발견 시 삭제/경고 처리 |
| **5** | 병해·갈변 | 썩음병, 잎마름, 갈변된 배추 부위 (가장 미세하고 집중 검출 필요) |
| **6** | 파·고추 | 김치 양념/부재료 중 오탐 위험이 높은 정상 식재료 |

## 3. 핵심 아키텍처: 3단계 데이터 생명주기 (Data Lifecycle)

```
[ data/raw/ ]          ──(읽기 전용 로드)──>   [ Tkinter GUI 도구 ]
(원본 900장, 불변 보존)                             │
                                                   │ (수정/추가 발생 시)
                                                   ▼
[ data/final/ ]        <──(build_final.py)──  [ data/work/ ] + [ manifests/ ]
(무결성 100% 승인본)       (엄격한 승인 조건)       (작업 라벨 분리)   (19개 검수 항목)
```

1. **RAW (`data/raw/`)**: 사용자 선택 원본 폴더. 시스템 차원에서 파일 쓰기/수정을 원천 차단하여 원본 보존 보장.
2. **WORK (`data/work/<dataset>/<split>/`)**: 작업 중 수정한 라벨만 저장. 다시 열었을 때 RAW보다 우선 로드되며 원본과 격리됨.
3. **검수 대장 (`manifests/dataset_manifest.xlsx / .csv`)**: 19개 필드(BBox 수, 상태, 작성자, 검수자, 비고 등)를 실시간 자동/수동 동기화.
4. **FINAL (`data/final/`)**: QA 전수 검증 통과 및 교차검수 완료 시에만 배치 빌드되어 교과 8로 인계.

## 4. 핵심 구현 기술 및 파이썬 알고리즘 (Core Python Logic)

### (1) 정규화 좌표와 원본 픽셀 간 상호 변환 (`coords.py`)
- **원리**: YOLO 형식($x_{center}, y_{center}, w, h$ 비율 0~1)과 4K 원본 픽셀 좌표($x_1, y_1, x_2, y_2$) 간의 완전 무손실 상호 변환.

```python
def yolo_to_pixel(xc, yc, w, h, img_w, img_h):
    """YOLO 상대좌표(0~1) -> 원본 픽셀 절대좌표(x1, y1, x2, y2)"""
    return (
        (xc - w / 2) * img_w,
        (yc - h / 2) * img_h,
        (xc + w / 2) * img_w,
        (yc + h / 2) * img_h,
    )

def pixel_to_yolo(x1, y1, x2, y2, img_w, img_h):
    """원본 픽셀 절대좌표 -> YOLO 상대좌표(0~1) 정규화"""
    return (
        (x1 + x2) / 2 / img_w,
        (y1 + y2) / 2 / img_h,
        (x2 - x1) / img_w,
        (y2 - y1) / img_h,
    )
```

### (2) 규칙 기반 무결성 자동 검증 엔진 (`validator.py`)
- **원리**: 사람이 놓치기 쉬운 8가지 치명적 결함을 정밀 검사.
  1. `PAIR_MISSING`: 이미지 ↔ 라벨 TXT 간 짝 누락
  2. `CLASS_DISABLED`: 정책상 제외된 Class 4(고무장갑) 잔존 여부
  3. `COORD_RANGE`: 0~1 범위를 벗어난 비정상 좌표값
  4. `BOX_OUT_OF_IMAGE`: 이미지 경계 밖으로 벗어난 BBox
  5. `TINY_BOX`: 식별 불가능한 초소형 노이즈 박스 (기준 미달 제거)
  6. `DUPLICATE_BOX`: 동일 위치 중복 박스 검출
  7. `BAD_FORMAT`: 숫자 형식이 아니거나 파라미터가 5개가 아닌 오류

### (3) 데이터 승인 및 최종본 빌드 조건 (`build_final.py`)
- **원리**: 아래 3대 무결성 조건을 만족하지 않으면 단 1장도 최종본으로 빌드되지 않도록 파이프라인 강제.
  - 조건 1: 모든 900장의 상태가 `검수 완료` 또는 `수정 완료`일 것 (검수 전/수정 필요/제외 잔존 시 빌드 거부)
  - 조건 2: **작성자 $\neq$ 검수자 (100% 상호 교차 검수 완료)**
  - 조건 3: Validation 오류(CRITICAL) **0건** 보증
