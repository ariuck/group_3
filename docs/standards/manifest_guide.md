### 프로그램이 자동으로 채우는 칸 / 사람이 채우는 칸

[💾 저장]을 누르면 프로그램이 `manifests/dataset_manifest.csv` 에 이 사진의 줄을 만들거나 갱신합니다.

| 구분 | 칸 |
|---|---|
| **자동** | No · 이미지 파일명 · 라벨(TXT) 파일명 · 원본 BBox 수 · 최종 BBox 수 · Class · TXT 줄 수 = 화면 BBox 수 · 상태 · 출처 데이터셋 · 원래 split · **검수일** |
| **사람** | 이미지 유형 · 위치 맞음 · Class 맞음 · 누락 객체 여부 · 발견된 문제 · 작성자 · 검수자 · 비고(수정 내용) |

- 같은 사진을 다시 저장하면 새 줄이 아니라 그 줄을 **갱신**합니다. `원본 BBox 수`는 처음 한 번만 기록합니다.
- **상태** 는 원본과 달라졌으면 `수정 완료`, 그대로면 `검수 전` 입니다. `검수 완료`는 사람이 직접 바꿉니다. (화면에서 `Enter` 를 누르면 원본과 같으면 `검수 완료`, 고쳤으면 `수정 완료`로 기록됩니다)
- **검수일** 은 상태가 `검수 완료` · `수정 완료` · `수정 필요` · `제외` 가 될 때 비어 있으면 **오늘 날짜**(`2026-10-06` 형식)를 프로그램이 적습니다. 이미 적힌 날짜는 바꾸지 않으니 엑셀에서 고쳐도 됩니다.
- 검수표 파일이 **비어 있으면**(0바이트) 새 검수표로 보고 처음부터 기록합니다. 머리글(첫 줄)이 기준 19칸과 다르면 파일을 덮어쓰지 않고 안내합니다.
- 사람이 정한 `수정 필요`(REVIEW 표시)와 `제외`는 프로그램이 덮어쓰지 않습니다. 사람이 적은 칸도 지우지 않습니다.
- RAW 밖의 이미지는 기록하지 않습니다. 검수표 머리글이 기준 19칸과 다르면 파일을 덮어쓰지 않고 경고합니다.

`R`, `S` 는 교과 8 에서 출처와 기존 train/validation 을 확인하기 위한 칸입니다. 프로그램 상단의 `출처: 데이터셋 / split` 표시를 보고 적습니다.

## 2. 상태 (L열) 5가지 — (제안)

| 상태 | 언제 | 이때 칸의 모습 |
|---|---|---|
| 검수 전 | 아직 열어 보지 않음 | 나머지 칸 비어 있음 |
| 검수 완료 | 기존 라벨이 맞아서 **수정 없이** 끝남 | 원본 BBox 수 = 최종 BBox 수, H·I·J = `O`, K = `X` |
| 수정 필요 | 문제를 찾았지만 아직 해결하지 못함, **또는 판단이 어려워 REVIEW 중** | `발견된 문제`에 이유 |
| 수정 완료 | 고쳐서 저장함 (BBox 추가·삭제·Class 변경·크기 수정) | `비고(수정 내용)`에 내용 |
| 제외 | 팀이 합의해서 이번 작업에서 뺀 것 | `발견된 문제`에 사유 (사진을 **임의로 제외하지 않는다**) |

대응 관계: 이전 기준 문서의 `DONE` ≈ **검수 완료**, `EDITED` ≈ **수정 완료**, `REVIEW` ≈ **수정 필요 + `REVIEW:` 표시**.

## 3. REVIEW(판단이 어려움) 표시 방법

검수표 상태 목록에는 REVIEW 가 없으므로 아래 규칙으로 표시합니다.

```text
상태          = 수정 필요
발견된 문제   = REVIEW: 이유 코드
비고(수정 내용) = 무엇이 애매한지 한 줄 설명
```

이유 코드 (BBox 기준서와 같음):

| 코드 | 뜻 |
|---|---|
| `class_ambiguous` | Class 를 정하기 어려움 |
| `bbox_boundary_ambiguous` | BBox 경계가 애매함 |
| `object_separation_ambiguous` | 겹친 객체를 나누기 어려움 |
| `too_small_to_identify` | 너무 작아서 식별 어려움 |
| `occlusion_ambiguous` | 가려져서 판단 어려움 |

코드에 없는 경우는 `REVIEW: Class 4 발견` 처럼 짧게 직접 적습니다. (Class 4 는 삭제하지 않고 이렇게 표시)

### REVIEW 가 해결되면

```text
애매함 → 교차검수자 확인 → 2명 이상 합의
        ↓
고쳤다 → 상태 = 수정 완료
그대로다 → 상태 = 검수 완료
        ↓
발견된 문제 칸은 지우지 않는다 (이력 보존)
비고에 최종 결정과 이유를 적는다
```

### 남은 REVIEW 확인 (엑셀)

`상태` 가 `수정 필요` 이면서 `발견된 문제`가 `REVIEW` 로 시작하는 행이 **0건**이어야 FINAL 로 넘길 수 있습니다.
(엑셀: 머리글에서 필터를 켜고 `상태 = 수정 필요` → `발견된 문제`에서 `REVIEW` 검색)

## 4. FINAL 로 넘기는 조건

- 900행이 모두 작성되어 있다 (`검수 전` 0건)
- `수정 필요` 0건 (= 미처리 REVIEW 0건)
- `검수자`가 작성자와 다른 사람으로 채워져 있다
- `출처 데이터셋`, `원래 split` 이 모든 행에 있다

## 5. 저장할 때 주의

- **프로그램은 CSV 에 기록**하고, `dataset_manifest.xlsx` 는 팀이 입력용으로 쓰는 틀입니다. 둘은 **자동으로 동기화되지 않습니다.**
  - 사람이 채울 칸은 CSV 를 엑셀로 열어 입력하고 **CSV UTF-8** 로 다시 저장합니다. (그래야 프로그램이 이어서 기록할 수 있습니다)
  - CSV 에는 선택 목록과 서식이 없습니다. 목록이 필요하면 xlsx 틀에 복사해서 쓰세요.
- 엑셀에서 CSV 를 열어 둔 채로 저장하면 프로그램이 기록하지 못하고 경고를 띄웁니다. (TXT 는 정상 저장됨)

- 엑셀 파일(`xlsx`)로 저장합니다. 머리글(1행)과 열 순서는 바꾸지 않습니다.
- CSV 로 내보낼 때는 **CSV UTF-8** 로 저장해야 한글이 깨지지 않습니다.
- 여러 명이 동시에 같은 엑셀을 고치면 충돌합니다. 각자 담당 범위의 행만 입력하고, 취합 담당이 합칩니다.
